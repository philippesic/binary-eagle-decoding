# Training audit: evidence and recommendations, October 6, 2026

**Verdict:** the project has credible native-target training plumbing and a real QAT improvement, but the evidence does **not** establish that it is training as effectively as reasonably possible. The clearest opportunities are better exposure accounting and learning curves, avoiding an unnecessary permanent reduction of the original TRAIN pool, and testing a few specific differences from the released training recipes. More hours alone is not a demonstrated remedy. Preserve EAGLE A8's paid 14.43 hours and the requested **12 cumulative trainer-hours for each remaining candidate**, with native checks at 4/8/12 hours.

This is an advisory audit, not authorization to change scientific recipes, datasets, duration, target precision, verifier, or sealed evaluation. No source or configuration was changed; no GPU/SSH/model execution occurred. The full objective remains six trained candidates plus three immutable original Q4 controls. RTX5080 is the only proposed experiment lane. The original block-Q4 recovery and final-held-out authority remain separate outstanding inputs.

## Most consequential findings

1. **Correct the interpretation of EAGLE exposure.** The original TRAIN pool contains **10,000 prompts**, not 4,218. The latter is the number actually consumed by checkpoint 344,724. Its 1,639,464 unique supervised rows are trace-row identities, not 1.64 million independent target-trajectory token positions. The admitted provider contains **10,000 prompts / 3,899,930 supervised rows / 822,166 rounds**. It stopped in **epoch 0**, having consumed about 42% of those rows/rounds, so there is no evidence of repeated full-corpus epochs or demonstrated convergence.
2. **Offline captured-prefix DSpark training is defensible.** The actual official Qwen3 DSpark training code uses target-token predecessors. Live student-prefix targets are a potentially useful ablation, not a prerequisite for a faithful first QAT run. Requiring this choice as though only live training were scientifically sound overstates the blocker.
3. **450/750 prompts are storage proposals, not model requirements.** They cover only 4.5%/7.5% of the original 10,000-prompt pool; even relative to EAGLE's consumed 4,218, they cover 10.7%/17.8%. Their bounded, short, single-shard selection is defensible for admission/pilot work, but not evidence that a 12-hour campaign has enough diversity. A sharded full-pool route is a legitimate alternative that needs implementation/admission, not a new architecture.
4. **The local DSpark objective is not the released objective in full.** `full_probability_l1` is CE **plus** L1, with default ratio 1:1 and uniform depth weights. Official Qwen3 uses CE:L1 = 0.1:0.9 and exponential position weighting. Local Markov parameters are frozen and the confidence head is outside the selected training path. These are deliberate restricted-QAT choices, not yet proven best choices.
5. **Current block training has an observability gap:** the main loop overwrites one status record, rather than preserving a loss/gradient/exposure time series. Fixing compact history is a higher-confidence operational improvement than immediately changing optimizers or increasing training duration.
6. **The measured primary-baseline result is still negative:** trained EAGLE A8 is **0.64536× Q4 request throughput**, despite a large improvement over its zero-update initialization. The strict target-only parity gate remains FAILED. Neither a low training loss nor the primitive 272/272 native proof changes these facts.

## Data: what is available, what was consumed, and what is missing

### Original corpus and coverage

The source manifest records pinned Databricks Dolly-15k prose, OpenAI GSM8K training arithmetic problems, and Magicoder OSS-Instruct code prompts. TRAIN contains 3,334 prose, 3,333 reasoning and 3,333 code prompts across 9,969 groups. Magicoder is approximately half Python (1,686/3,333); reasoning is specifically GSM8K arithmetic, not broad formal/scientific reasoning. Prose includes eight Dolly categories. These are sensible complementary domains, but three balanced labels do not establish representative modern assistant/tool-use/multilingual/long-context coverage.

Original prompt lengths are predominantly short: median **87**, p95 **393**, maximum **1,301** input tokens; 5,760 are below 128 and only 167 are 512–2,047. The manifest's 1,502,567 “unique input tokens” means token positions counted once per selected prompt, not distinct vocabulary items, generated labels, or optimizer presentations. Target-generated responses give valuable alignment, but response lengths, EOG rates, and actual native context lengths must be measured separately. Do not describe the original corpus as long-context training on this evidence.

The manifest removed 118 exact-normalized and 214 approximate-near duplicates before grouped splitting. It records explicit group/exact cross-split checks and opaque legacy exclusions, and expressly does not claim semantic decontamination. Keep these qualifications. Group disjointness is stronger than checking filenames; it is still not a guarantee against all benchmark contamination.

The stopped receipt reports 4,218 consumed prompts and 1,639,464 unique supervised rows. Frozen `continuous_qat.py:1388` increments labels and inserts keys `(capture_id,prompt_id,round_index,row_index)` after an update; current equivalent is [continuous_qat.py](../../src/w1a1_eagle/continuous_qat.py) at 1416. The frozen checkpoint is epoch 0, cursor 345,558, step 344,724. Freshly copied `prepared-ready.json.teacher_coverage` confirms the provider actually admitted 10,000 prompts, 3,899,930 supervised rows and 822,166 rounds across 320 capture shards; this is stronger than prompt-manifest availability alone. `status.json.presented_supervised_tokens` equals 1,639,464, matching the unique trace-row counter. Thus these are **observed exposure counters**, not corpus capacity. They count distinct captured training conditions: different rounds can share target context or token positions, so “unique rows” must not be inflated into independent examples. Unsupported/invalid rows also explain why cursor and optimizer steps differ.

The frozen iterator keeps balanced shard order, then prompt/round order (`scripts/w1ax_multishard_provider.py:249,352`; `scripts/w1ax_capture_provider.py:878`). It is deterministic, not a newly shuffled corpus each epoch. Serial rounds within a prompt create correlated updates. Whether the first 4,218 retain the full manifest's domain/length proportions is **not established** by the aggregate counter. A cheap index/cursor join should report actual consumed domain, category, input/generated length, labels per depth and unique accepted-prefix hashes. Do not reread sealed content to do this.

### Reusing the “same EAGLE dataset”

There are three different reuse claims:

| Reusable item | Assessment |
|---|---|

| Native target generation/capture machinery and shared block payloads | Reuse after a new source-bound capture/admission. DSpark and DFlash can share full raw block captures when their source/prefix/role joins match. |

The current source's native layer-input indexing is explicit (`block_data.py:27,645`; `capture_nine_model_train_data.py:51`). Official DeepSpec config uses zero-based target-layer IDs `[1,9,17,25,33]`; do not call the one-step numerical naming difference a proven tap bug. Verify tensor semantics at the extraction boundary, not labels alone.

The 450/750 proposals select from **shard 0**, require original input length ≤512, reserve 32 fit and 16 validation prompts per domain, and choose subsequent eligible rows in order. With 128 new tokens, they allow at most 56,700/94,500 label positions per pass. Those upper bounds are only 3.46%/5.76% of the paid EAGLE unique-row count, and the row definitions differ. Repeated epochs cannot recover missing prompt diversity. First-shard and length filtering are known restrictions, not proven representative sampling.

**Recommendation:** offer a scope-preserving option based on the original full TRAIN pool, using bounded shards and original group separation. Keep 450/750 as explicit pilots or as a user-chosen constrained experiment. If forced to choose only those two for an otherwise fixed 12-hour run, prefer 750 for breadth, conditional on storage admission; do not call it sufficient. Reusing all 4,218 consumed prompt IDs is a reasonable matched-exposure subset, but it still is not “the full original corpus.” Changing role exclusions/selector requires a new immutable selector, not rewriting the original manifest.

### Storage and streaming

The exact-soft requirement is expensive: each retained F32 teacher row is `151936 × 4 = 607744` bytes, versus `5 × 2560 × 4 = 51200` feature bytes per context position. At 128 outputs, 126 teacher positions per complete chain are retained. Scaling to thousands of prompts can exceed the observed disk reserve before checkpoints. This is a real resource issue, not evidence for a scientifically optimal subset size.

Current `block_data.py:1031` copies one block's full context and seven teacher rows; cache mappings are bounded and closed. This prevents the previous unbounded retained-map problem, but it neither implements a cycling full-corpus capture cache nor proves production memory admission. Fixed anchors are at stride seven (`block_data.py:42–50`), and epoch shuffling changes chain order, not anchor positions (`1087–1139`).

A faithful scalable route is: immutable global TRAIN selector → bounded deterministic native capture shards → content-addressed manifests → training iterator with exact shard/cursor ownership → archive or reproducibly recapture evicted shards. Preserve full context, all vocabulary logits, F32 teacher contract and exact target/source pins; never substitute top-k or half precision silently. Capture time/disk and trainer time need separate accounting. If recapture is intended to be byte-identical, establish deterministic replay; otherwise preserve each actual capture's identity. Keep enough shards to avoid excessive target reloads and domain starvation. This is engineering work with an admission cost, not a capability already demonstrated.

A different possible storage design retains native final hidden states and applies the frozen head on demand, as official DeepSpec does in its model. That does **not** automatically reproduce native F16 execution/logits; it needs a new numerical/export contract and is a lower-priority alternative to exact sharding. DFlash hard CE can omit bulk soft logits, but DSpark's selected objective cannot. Avoid forcing DFlash to pay additional unused full-logit storage when captures are no longer shared.

### Conditioning and exposure bias

The strongest correction to the pending choice is that **teacher-forced captured-prefix DSpark is supported by the actual released source**: it builds predecessors from the anchor plus `target_ids[..., :-1]` and applies Markov logits to those IDs (`modeling.py:473–492`). It aligns target logits from the same clean target sequence. [Pinned model code](https://github.com/deepseek-ai/DeepSpec/blob/005e03b81cec38b7da6399833d609ee89a2587f2/deepspec/modeling/dspark/qwen3/modeling.py).

“On-policy” must be qualified. Target-generated continuations are on the **target's** distribution; they need not be current-student proposal trajectories. Current local `block_qat.py:395–451` supports both target-predecessor training and live current-student prefixes. Static native-greedy replay correctly stops supervision at the first mismatched predecessor using a cumulative mask (`452–459`), rather than applying stale teacher distributions to a different history. Live queries must keep the whole prefix, including wrong proposals. It is an experimental alternative, with substantial target coexistence/query cost, not an automatic improvement per GPU-hour.

For EAGLE, the recurrent rollout keeps student states/KV attached within the captured chain (`recurrent_rollout.py:94–180`), but feeds historical captured proposal IDs. Context cache rebuild uses `no_grad` (`:75`) and therefore truncates backward credit through old context. This is an explicit approximation with sensible memory benefits, not full-sequence backpropagation or current-student on-policy training. Quantization changes proposals, so stale-prefix coverage is a plausible bottleneck. Measure current-student/capture prefix agreement by depth on unsealed diagnostic traces before paying for refresh. Do not mix teacher rows across differing prefixes to conceal the problem.

### Loss choices and prioritization

At `block_qat.py:462–480`, local loss is weighted mean `(CE + probability_l1_weight × sum_vocab|p_d-p_t|)`. It correctly normalizes over valid tokens, not vocabulary cells. With defaults 1 and depth decay 1, it is a 1:1 mixture. The name `full_probability_l1` alone is not an adequate recipe description. Official CE:L1 = 1:9 in relative terms; setting local weight to 9 matches that ratio but gives a different global loss scale, which interacts with gradient clipping and Adam epsilon. A faithful ablation must explicitly set normalization and inspect clipping, not silently multiply one coefficient.

L1's direct acceptance interpretation in the DSpark paper assumes probability-ratio speculative sampling. The current campaign is native greedy/sample-and-match behavior; do **not** claim `1 − TV` equals its measured greedy acceptance. Here hard top-1 accuracy, target margin and conditional prefix survival are indispensable diagnostics. [DSpark objective and verification assumptions](https://arxiv.org/html/2607.05147v1).

Soft CE/KL can preserve alternatives that hard CE discards; forward KL differs from soft CE only by teacher entropy when teacher is frozen. They are not interchangeable with L1. Feature reconstruction is lower priority: EAGLE-3 deliberately removes its older feature-prediction constraint. For QAT, a small auxiliary dense-drafter feature/logit loss remains a hypothesis, especially for binarized fusion, but can conflict with the restricted binary representation. Do not add it without a controlled native-acceptance result.

**Best first recipe hypothesis:** position weighting for the seven-slot block (official gamma 4 corresponds to local geometric decay `exp(-1/4) ≈ 0.7788`). It directly addresses prefix rejection and is cheap to implement/evaluate. **Next:** DSpark CE/L1 relative weighting. Test them separately if attributing causality; a combined “official-like” arm is only a package comparison. Randomized anchors are also source-supported, but require teacher-index coverage, masks, cursor reproducibility and admission; merely shuffling existing chains is not equivalent.

### QAT, optimizer and batch size

The paid run's **actual immutable config** says fixed activations, `affine_weights=null`, `binary_optimization=null`, `fusion_correction=null`, `persistent_sign_diagnostics=false`, sign LR 1e-3, scale LR 1e-5, warmup 100, depth decay 1, checkpoint every 250, and `development_every=9223372036854775807`. It therefore did not use the learned-activation/affine candidate in `configs/qat_a8_comparison.json`. The fresh `effective-config.json.config.objective` explicitly confirms `hard_ce`; its omission in the immutable-config serialization is a compatibility convention. Frozen `continuous_qat.py:1230` applies warmup then constant LR; no cosine decay is hidden in that loop.

**W1A8 means one-bit weights and eight-bit activations**, not eight-bit weights. EAGLE trains all nine selected linears including its vocabulary head; blocks train fifteen FFN projections plus fusion, leaving private full head/embedding, attention/norms and DSpark Markov buffers fixed (`block_qat.py:260–322`). These are materially different compression scopes, so architecture comparisons also reflect coverage choices.

Current hard-sign STE uses clipped identity in latent weights; optimizer updates floating latent signs and scale offsets, followed by latent clipping and nonnegative scale projection. A8 uses dynamic quantization, and A1 uses sign with mean-absolute activation scale; scale is detached in that activation surrogate (`recurrent_binary.py:9,54`; `recurrent_qat.py:94–116`). Blocks use AdamW without weight decay, one seven-label block per step, max gradient norm 1, no warmup/scheduler or accumulation in `block_qat.py:489–546` / `train_nine_model_qat.py:730–788`.

These are defensible baseline QAT mechanics, but not optimized by proof. Monitor per-layer latent magnitude/near-zero fraction, bound occupancy, sign flip and flip-back rates, scale collapse/movement, activation saturation (meaningful for A8), gradient norm/clipping and finite values. The EAGLE logger already records several of these; the frozen run disabled persistent sign diagnostics. Finite gradients establish numerical health, not useful learning. The copied final status contains 10,233 sign flips at step 344,724 (rate 4.689e-5), ~3.381 billion cumulative flips, and pre-clip gradient norm 121.23 against cap 1. Thus the signs were not globally frozen. This single final observation cannot establish a typical clipping rate or beneficial versus oscillatory flips; summarize windows before diagnosing the optimizer.

Binary optimization literature motivates tracking sign inertia instead of interpreting a latent weight as an ordinary weight; it does not establish Bop as superior for this drafter. Learned-step-size work supports learned quantizer parameters in other settings, not a guaranteed W1A1 recovery. [Bop paper](https://arxiv.org/abs/1906.02107), [LSQ paper](https://arxiv.org/abs/1902.08153). Prefer a short latent-inertia/LR diagnostic if signs never move or churn; do not launch an optimizer sweep by default.

Microbatching several blocks can improve utilization and reduce noisy updates, but gradient accumulation alone does not make forward/backward cheaper. It changes effective batch, update count and clipping frequency. Benchmark labels/second and acceptance per trainer-hour, with native arithmetic and full masks preserved. Official batch sizes cannot simply be copied onto a 16 GB 5080. Similarly, A8→A1 warm starts, gradual quantization or freezing the sensitive head/fusion are testable alternatives, not proven improvements; changing the approved direct-A1 route or precision coverage requires a human research choice and must charge all stages to the selected allocation.

## Duration: what twelve hours can and cannot mean

The completed run used 51,950.921720 trainer-seconds for 344,724 updates: **6.6356 updates/s**, **31.5579 unique trace labels/s**, **4.7559 labels/update** averaged across that run. A purely illustrative same-rate 12 hours would produce ~286,657 updates/~1.363 million trace labels. It is **not** a prediction for DSpark, DFlash, A1, later longer contexts, or a changed batch recipe. Their actual labels/update and cost differ.

The two observed 1,000-update TRAIN windows contain 4,869 and 4,631 labels; weighted CE is 4.84957 then 5.76897, pooled **5.29775**. Different serial examples make this unsuitable as a convergence slope. Both report finite gradients. Neither is dev loss or native acceptance, and the windows end at step 340,251 rather than the final 344,724. Current receipts do not supply an intermediate native EAGLE learning curve. Initial-to-final improvement does not locate a plateau or prove more hours will close the Q4 gap.

Keep exactly 12 cumulative trainer-hours for each remaining model and the selected ordering. At 5/15 minutes measure actual update/label rates and estimate first-pass coverage; at each 2-hour health check record cumulative unique prompts, unique `(chain,anchor,label-position)` conditions, repeated presentations, epoch, CE/L1 separately, per-depth top-1 and clipping/saturation. At 4/8/12 hours collect the prescribed native metrics. Continue the healthy authorized allocation even if early results are weak; failed correctness/nonfinite/resource gates warrant a safe checkpoint and diagnosis, not an arbitrary smaller research budget.

Evidence for extending training later would be reproducible improvement on a fixed unsealed dev set from 4→8→12 hours, an improving primary throughput ratio, and no widening train/dev gap. Evidence against simply adding hours would be flat native acceptance with falling train loss, repeated small-pool exposure and worsening dev results, persistent unusable sign dynamics, or a measured draft-cost ceiling. No public paper establishes an optimal number of hours for this particular binary 5080 setup.

## Evaluation and the actual baseline

This audit independently recomputed all **720 clean measurement records** across the two existing sweeps, excluding warmups/diagnostics:

| Arm | Accepted/proposed | Acceptance | Request tokens/s |
|---|---:|---:|---:|
| Trained-sweep Q4 EAGLE | 8,025/30,290 | 26.4939% | 143.87492 |
| Trained EAGLE A8 | 4,765/46,125 | 10.3306% | 92.85084 |
| Initial-sweep calibrated zero-update A8 | 1,485/62,050 | 2.3932% | 70.45922 |

Each arm has 120 requests and 14,290 output tokens, from five repetitions of 24 development prompts. Trained versus paired Q4 is **0.64536×** request throughput; its accepted/round is 0.5080 versus Q4 1.3038. The 4.32× acceptance improvement over initialization is useful learning evidence, not the primary success gate. All 120 A8/Q4 raw sequences match in each sweep; target-only matches only 115/120, representing the same one of 24 prompts repeated five times. The strict target-only failure remains FAILED; existing near-tie evidence narrows the diagnosis but does not waive it.

Five deterministic repeats do not create 120 independent quality prompts. Acceptance ratios involve correlated positions and denominators that change with rejection behavior. Report per-prompt/per-domain accepted-prefix length, depth-conditioned acceptance and request time; use paired, prompt-cluster uncertainty for generalization and separate repetition variance for timing. A 24-prompt dev set can identify a large deficit but is fragile for small gains or domain conclusions. Do not compute a binomial interval as if all 46,125 proposals were independent draws.

Preserve F16 target/verifier/KV, prompt IDs, chat/thinking mode, 128-output cap, context/batch settings and clean paired order for the campaign. Add wider unsealed validation only through an explicitly frozen disjoint selector; keep the sealed final set for one final comparison after recipe choices. Longer generations/context and realistic domain strata matter for external validity, but changing them is a separate labeled evaluation, not a replacement denominator. Recover the literal original Q4 files rather than silently re-quantizing new controls.

Native model admission must compare real feature fusion, masks, cache positions, draft logits/decisions and exported arithmetic. Primitive 272/272 tests, Linux FD stress, CPU backward and planning packets are useful prerequisites, not model-level quality/memory/performance evidence. Timebox cross-backend drift work to whether it changes labels, gradients, proposals or conclusions; avoid demanding universal bit identity as a reason never to train. Do not use a tolerated training/native numeric difference to redefine the existing failed target-only output gate.
