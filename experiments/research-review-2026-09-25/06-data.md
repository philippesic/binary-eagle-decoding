# 6. Training data, state alignment, vocabulary support, and supervision

Local-only source review, 2026-09-25. No web, GPU/SSH, training, or repository mutation. Recommendations are proposed experiments, not results. Existing final sets stay sealed for model selection. Optimizer and STE changes are outside this review.

## Main finding

The failed pilot demonstrably trained the wrong *proxy for acceptance*: reconstruction of the original draft head on a frozen mixture of ordinary/binary rollout states. That proxy is legitimate compression training, but neither its teacher nor its checkpoint criterion is the target verifier. Lower KL therefore does not establish improved accepted prefixes. There is **no demonstrated off-by-one or vocabulary-map bug** in the existing implementation. There is a demonstrated lack of metadata needed to test target alignment, and a material train/deployment state-distribution mismatch (branching PyTorch trees versus native greedy chains).

The highest-value next action is a bounded, labeled-state audit, followed by the already proposed target-aligned head experiment if the audit passes. Do not launch broader QAT or replace the vocabulary before measuring the recoverable error.

## Established evidence

1. **The teacher is the drafter, not the target.** Capture saves `ordinary_head.weight`, shape 32,000 × 2,560 (`scripts/capture_qat_head_inputs.py:310–320`). Both training and validation compute `F.linear(batch, teacher)` (`scripts/train_qat_head.py:340–359, 489–498`); KL is `KL(teacher || student)` over these 32,000 logits (`:319–337`). “Full-vocabulary KL” in the pilot report therefore means the full **draft** vocabulary, not the 151,936-token target vocabulary. Best checkpoint selection uses minimum cached validation KL (`:517–530`). There are no target labels/logits in the capture. The observed result—KL 2.50634→1.01696, binary acceptance 1.67668→1.56522, ordinary execution of trained head 2.31659→1.81331—is evidence that this proxy failed here, not proof that distillation generally fails (`experiments/qat-head-pilot-results.md:32–48, 73–105`).

2. **This was already partially on-policy capture, not pure teacher forcing.** Each prompt executes real `eagle_generate` under ordinary or untrained head-W1A1 settings, with alternating prompt assignment (`scripts/capture_qat_head_inputs.py:82–84, 343–360`). Within a generated tree the later inputs are draft-selected tokens/recurrent states. However, only one policy sees each prompt, policy is confounded with prompt identity, and the trained head never refreshes that state distribution. Normalization and all upstream weights remain frozen in a head-only experiment, so changing the head changes future inputs by token selection and tree pruning, not by a direct change to the same-prefix upstream computation.

3. **Capture lacks the alignment key.** Metadata has prompt, policy, draft-call ordinal, head-call ordinal/depth, row index only (`scripts/capture_qat_head_inputs.py:189–212`). It lacks tokens, prefix/path hash, parent ID, absolute position, retained-node index, target verifier row, and accepted-path status. Existing rows cannot safely be relabeled by merely shifting the final generated text. A sibling branch needs the target distribution conditioned on *that sibling's full ancestor prefix*, even if that branch is later rejected.

4. **Native state semantics are explicit.** At draft cache position P, the decoder consumes `(token[P+1], fused_target_features[P])` (`third_party/llama.cpp/common/speculative.cpp:658–706, 732–755`). Its logits predict token P+2. The next speculative step consumes the just-proposed token and the previous **pre-normalization draft state** (`:782–820`); the graph exports this state before the head RMSNorm (`third_party/llama.cpp/src/models/eagle3.cpp:462–489`). A dataset pairing target features[P] with token[P] or supervising token[P+1] would be wrong, but no such target-labeled dataset exists in the pilot. Target features are taken at three configured layer inputs (or final pre-norm boundary), and target embeddings are used when the draft has none (`common/speculative.cpp:513–526`; `src/models/eagle3.cpp:327–348`). Capture/replay must preserve layer-index convention, norm placement, feature order, and positions.

5. **The native/PyTorch proposal distributions differ.** Native draft chooses the top candidate and rolls out one chain (`common/speculative.cpp:782–820`); the frozen native example uses max draft length 5 (`configs/native_benchmark.toml:32–40`). PyTorch is configured with top_k=10, depth=5, 59 selected draft nodes (`configs/pytorch_w1a1.toml:18–30`). Cached AngelSlim source shows one head row for the seed and ten rows for each of five recurrent levels: **51 pre-head rows per complete tree**, only 1/51 at root before reservoir effects. Candidate pruning uses cumulative scores and global top selection; root correctness, branch ranking, and path continuation matter differently from mean row KL. The native p_min mechanism exists (`common/speculative.cpp:797–804`), but its default is 0 (`common/common.h:330`); do not claim threshold changes caused this pilot failure.

6. **Uniform capture emphasizes numerous deep/off-path rows.** Reservoir sampling is uniform across individual rows within each prompt, followed by optional global subsampling (`scripts/capture_qat_head_inputs.py:87–115, 215–227`). Training samples uniformly from retained rows (`scripts/train_qat_head.py:466–491`). A separate `tree_depth_index` exists, but no depth-conditioned loss/selection is used. Equal per-prompt caps are useful, yet make long/short requests differ from actual runtime exposure; 32,768 rows are not 32,768 independent prompts. Report prompt/family-level uncertainty, not row-level confidence intervals.

7. **Final unverified trees are a capture hazard.** The cached generation source calls `update_inference_inputs`, obtaining the next draft tree, before `should_stop` (`/tmp/angelslim-pinned-eagle3-model.py:546–583`). Thus head calls can occur for a terminal next tree that will never be target-verified. The old hook has no round-verification status and can retain these rows. This is harmless for draft-head reconstruction but becomes missing-label data for target supervision. Also, pruned nodes may lack a corresponding verifier row, and retrieve-path padding uses -1 (`/tmp/angelslim-pinned-eagle-base.py:382–425, 427–459`). These cases need explicit disposition, never guessed labels or negative indexing into logits.

## Vocabulary support: checked locally, mass still unknown

A read-only standard-library decode of local `models/hf/Qwen3-4B_eagle3/model.safetensors` reconfirmed `d2t` I64[32000], `t2d` BOOL[151936], 32,000 unique strictly increasing absolute IDs `i+d2t[i]`, minimum 0, maximum 151668, and exact equality between these IDs and true positions in `t2d`. This corroborates `experiments/qat-revisit-plan.md:57–70`. `t2d` is a membership mask, not an inverse-index tensor. Build an explicit inverse array initialized to -1; test `inverse[draft_to_target[i]] == i`. Check the GGUF uses absolute IDs, while HF uses offsets.

Only 21.06% of vocabulary *types* are represented; this does **not** mean 78.94% of predictive probability is missing. No target probability-mass measurement was available locally. For every valid state, compute in float32:

- `m = sum_{v in draft_support} p_target(v)` and `outside_mass = 1-m`, with quantiles and per-category/depth/path status.
- Whether the actual verifier argmax is representable; whether ordinary and binary top-1/top-k contain it; target rank and logit margin of the draft token.
- First unsupported target-greedy token per reachable prefix. A support-only oracle caps accepted chain length at the first unsupported target token (under fixed verifier semantics). This is more relevant to greedy acceptance than average missing mass.

Keep restricted target probabilities and original normalization distinguishable: `p_restricted(v)=p_target(v)/m` has discarded missing mass. Hard CE is undefined for an unmapped label. Never remap it to index zero or pretend a restricted argmax equals the target argmax. Recommended bounded first treatment: include unmapped rows in diagnostics and denominators, exclude only their hard-label CE with an explicit mask/count, and retain any prespecified draft regularizer. Do not add an “other” output class—it has no deployable token under the existing fixed head. If unmapped labels dominate reachable early-depth errors, stop head-only acceptance-recovery claims and take the vocabulary-support decision to the user. Weighting soft restricted-target CE by m is a coherent alternative (`-sum_support p_target log q`), but is a different objective to freeze before training, not a late patch after final evaluation.

## Splits and preprocessing

Exact content/ID isolation is actively enforced by old capture/trainer (`scripts/generate_qat_head_prompts.py:159–169`; `scripts/train_qat_head.py:113–154`). No evidence of exact train/validation/held-out leakage was found. Nevertheless the pilot's 40 reasoning questions are five arithmetic templates with eight parameterizations, shuffled at individual-question level (`scripts/generate_qat_head_prompts.py:107–140, 172–190`). Read-only counts show all eight validation reasoning prompts reuse a training template: worker-rate 3 validation/5 train, border-area 4/4, bead sampling 1/7. This weakens the cached validation's evidence for family generalization; it does not invalidate the separate held-out negative result.

The revisit generator assigns whole named topic/template families (`scripts/generate_qat_revisit_prompts.py:449–489, 505–522`). Local hashes match the frozen report exactly: 96 train / 24 development / 24 final, 32/8/8 per category, 30/9/10 named topic families. Its historical audits test exact content and IDs, not semantic near duplicates (`:492–502`). Families are manually assigned labels and `template_family` is derived from topic; they are useful controls, not proof of zero semantic overlap. Do not change the sealed final set based on results. Add a documented near-duplicate audit on train/development and prior data; interpret the final family split as the existing predefined benchmark.

Both old capture and evaluation share `encode_prompt`: apply target tokenizer chat template, generation prompt, and explicit thinking flag, with tokenization inside the template (`scripts/evaluate_pytorch_w1a1.py:145–154`; capture `:351–353`). This is good evidence against a capture/evaluation preprocessing mismatch. Native uses its Jinja template and GGUF tokenizer, so freeze/hash rendered prompt **token IDs**, BOS/EOS/stop IDs, whitespace, thinking prefix, effective max length, and target/draft tokenizer metadata when claiming cross-runtime alignment. Matching JSON prompts and `thinking=false` alone does not establish identical tokenized prefixes. Do not truncate a target label without recording that it lies beyond the capture horizon.

## Proposed bounded design and priorities

### P0: alignment and recoverable-error audit, no optimization

Use a small predeclared train/development subset, e.g. two prompts per category, both ordinary and unchanged binary policies on the **same prompts**, fixed output cap and existing protocol. No final prompts. Record each head state's unique ID, round, parent/path and prefix-token hash, root seed, absolute target and draft-cache positions, recurrent depth, feature source (target-fused or draft-recursive), dtype/norm stage, candidate draft IDs and mapped IDs, chosen/pruned status, verifier raw row, retrieval-path row, and eligible/accepted-path flags. Record EOS/padding/unverified cases explicitly. Hold the teacher/verifier and mapping fixed.

Instrument the actual verifier logits and join by ancestor path/node identity. The logits *after the parent token* supervise the next proposed token. Root head predicts after the target-selected seed; first proposal must match verifier seed-row argmax. Child state predicts after its own parent node; never use the child's own next-token row to label the token that created it. Test cache reset, zero/partial/full acceptance, boundary between microbatches, repeated token values on different branches, pruned branch, EOS and -1 padding. Repeated token values are not unique alignment keys.

Use exact-prefix target replay only as a diagnostic. The project already documents BF16 tree-versus-incremental target argmax ties, so do not require bitwise cross-batching logits or silently overwrite actual verifier labels with replay labels. Require exact token/path/position mapping, then report numerical disagreements with margins as a separate verifier-consistency issue. Block training for structurally ambiguous joins, unexplained label shifts, nonfinite logits, or map mismatch.

Produce error decomposition by root/recurrent depth and eligible prefix: unsupported target ID; supported ID missing from ordinary top-k; additional binary ranking loss; branch-selection/pruning loss. This establishes whether head training has recoverable room and whether an off-path dataset dominates its reported loss. Do not assume vocabulary expansion or recurrent training is needed merely because overall acceptance is low.

### P1: one target-aligned head recipe using audited data

Keep the existing revisit cap/checkpoint protocol (`experiments/qat-revisit-plan.md:82–104`), original head initialization, and fixed quantizer. Cache paired ordinary/binary trajectories under the same prompts, with prompt-level caps and explicit depth strata. Ensure root and reachable-prefix rows are represented, preserve sampling probabilities, and report both stratified and deployment-weighted metrics. Do not blindly use inverse-frequency weighting to make all depths equally important; depth is a selection bias and an operational importance variable. Freeze one allocation and loss before optimization.

The current plan's mapped target-argmax CE plus a small fixed original-draft KL is a defensible first experiment for greedy acceptance. Evaluate cached target CE/top-1 margins, support coverage, original-head KL and depth curves, but choose among steps 0/100/250/500 by **online** development accepted drafts/round, as already planned. New online checkpoints are a test of state-distribution shift as well as head fit. If none improves unchanged binary acceptance, stop this recipe. If one improves, evaluate once on final; do not retune on that result.

Because the intended deployment uses a chain, collect a small matched native-chain labeled trace and compare depth/state/error distributions before expanding investment. Prefer native-state capture for a native head-only objective once its audit machinery is ready. Changing from PyTorch-tree development to native-chain development is a protocol decision to freeze explicitly; it must not be chosen opportunistically after inspecting final performance.

### P2: at most one bounded rollout-refresh extension, only if P1 identifies drift

If cached target accuracy improves while fresh online development acceptance does not, inspect *new* rollout states from the trained head on training prompts. Compare loss/rank/margins to initial-policy states at matched depths and prefixes. A single prespecified refresh/mix of training states is a reasonable next experiment; pure teacher-forced token sequences would again miss the student's recurrent prefixes. Keep target labels conditional on the actual draft-generated prefix. For wider-layer QAT, replay full recurrent computation with correct hidden/KV states and detached fixed target supervision; old pre-head caches cannot train upstream dynamics. No unbounded iterative dataset aggregation and no final-set refresh.

## Metrics and stop gates

Primary: accepted draft tokens / rounds; preserve accepted/proposed counts, emitted/round, acceptance survival `P(L>=d)` and conditional continuation by depth, per-prompt/category values. Secondary: support oracle length, unsupported-argmax frequency, outside-mass quantiles, target top-1/top-k agreement/rank/margin, actual verifier disagreement versus exact-prefix replay, per-depth teacher KL, policy-source and root/off-path/accepted-prefix proportions, total and retained rows, exclusions by reason. Use prompt/family resampling for uncertainty. Tree proposed-node ratio and chain proposal ratio are not interchangeable.

Stop before training if label joins or support handling are unresolved. Stop the bounded recipe if online development does not beat the unchanged binary head. Do not infer native throughput from PyTorch acceptance. A final quality improvement advances only to fixed-input export/native parity and matched native FP16-EAGLE **and Q4_0-EAGLE** comparisons on the same target/verifier/hardware. Identical-input quality and deployment-state quality are complementary diagnostics.

## Uncertainties and counterarguments

- No evidence establishes misalignment as the cause of the pilot's failure: the pilot had no target labels to misalign. Better original-head fit is reasonable compression supervision and could work with different capacity/state weighting; this experiment simply did not.
- Head-only update cannot repair upstream binary-state damage under all-group W1A1. W1Ax quality results should inform that later coverage decision.
- Hard target-argmax CE may improve greedy ranking but hurt branch probability calibration. Soft restricted-target distillation may preserve ranking uncertainty but must expose missing support mass. One fixed objective is preferable to searching both on a tiny development set.
- Frozen captured states reduce variance and cost; full online training is not necessary to run the next bounded head gate. A data-refresh experiment is justified only by measured drift.
- Target probabilities depend on BF16/FP16 arithmetic and verifier batching. The 5080 PyTorch evidence cannot be treated as a measured SM75 native quality/speed result.
