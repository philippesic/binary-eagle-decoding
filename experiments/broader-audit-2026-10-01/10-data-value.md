# More learning value from existing native teacher work

Date: 2026-10-01. Source baseline: `f0bb92dda687d908b3cffe084510b3be757df54f`. This audit reads source and primary research only. It ran no tests, training, accelerator or remote work, model loads, large capture reads, or sealed evaluation. The live 10,000-prompt paired A8/A1 recipe remains the control. Recommendations below require a new recipe; they do not alter its frozen provider or resume identity.

## Verdict and source findings

Prepare a coverage-constrained **whole-round selection provider** first. It can reduce future training presentations using existing labels, with no new teacher inference. Second, prepare an indexed raw-feature provider that eliminates the selected-F32 copy while preserving exact bytes. A third, smaller deliverable is a cost-aware prompt chooser for explicitly requested future refresh or reserve capture. None establishes quality or SM75 throughput before native evaluation against Q4_0 EAGLE.

`continuous-w1ax-data-preparation.md` records 3,334 prose, 3,333 code and 3,333 arithmetic prompts, totaling 1,502,567 chat input tokens. These are prompt tokens, not supervised labels or independent semantic coverage. The 87-token median and 393-token p95 describe chiefly short and medium inputs; arithmetic is GSM8K, not general reasoning. Dolly categories and Magicoder languages provide useful strata, but identical token totals can still represent very different task coverage. The 24,507-prompt reserve is unbalanced and requires explicit promotion.

`StreamingNativeProvider` freezes shard then prompt/round order. `ContinuousTrainer.run` makes one independent optimizer update per lane on each supported round, uses mean CE over supported rows, skips wholly unsupported rounds, and repeats the iterator at subsequent epochs. Its unique-row key includes capture, prompt, round and row position. That counts distinct captured supervision presentations; it is not proof of unique complete label prefixes or independent information. Both lanes already share the same round and teacher capture, so there is no additional twofold teacher saving to claim.

`prepare_recurrent_native_features.py` already unions accepted prefix keys across anchors and writes one selected row per key. Duplicate retained features must agree numerically. `w1ax_continuous_stages.py` already hardlinks immutable raw feature bytes and captures no full target logits under its label-only policy. Thus ordinary feature deduplication and replacing full logits with labels are completed work. The remaining storage opportunity is the additional selected-F32 array and verbose prefix metadata, not imaginary per-round copies of all features.

## What the literature supports

[EAGLE-3](https://arxiv.org/html/2503.01840v1) shows that removing the feature-prediction constraint and training through recurrent predicted states enables gains from more training data. Its training uses target-generated responses and much larger instruction corpora. This supports preserving later-state supervision and questioning prompt count as sufficient evidence; it does not establish a pruning ratio for binary QAT. Its domain-dependent acceptance also argues against choosing data solely by label frequency.

[Medusa](https://arxiv.org/html/2401.10774v3) uses target self-distillation when public instructions do not match the target output distribution. This supports keeping native target labels rather than substituting Dolly answers, code solutions or arithmetic references. Its backbone adaptation and relaxed acceptance variants do not transfer to this fixed-target, fixed-verifier experiment.

[GRAD-MATCH](https://proceedings.mlr.press/v139/killamsetty21a/killamsetty21a.pdf) selects weighted subsets that approximate training or validation gradients, with practical last-layer approximations and warm starts. [LESS](https://arxiv.org/html/2402.04333v3) adapts influence scoring to Adam, uses warmup LoRA gradients and random projections, and normalizes gradient directions to avoid short-sequence bias. Both motivate a later measured selection study. Computing their scores requires model work; they are not a CPU metadata shortcut. A dense 32,000-class head gradient or one fixed checkpoint's ranking is especially poor evidence for useful binary sign movement across nine projections.

[DSIR](https://arxiv.org/abs/2302.03169) performs inexpensive distribution matching using hashed n-grams. Its evidence is language-model pretraining, not speculative acceptance, but its feature machinery fits a CPU-only prompt selector. [BERT on a Data Diet](https://arxiv.org/abs/2211.05610) finds that early GraNd/EL2N scores can be unreliable in NLP and that removing the hardest tail can help. This cautions against assuming the largest loss, smallest margin or largest gradient always identifies the best binary example.

## Deliverable 1: versioned whole-round selection

In two CPU days, implement a sidecar selection manifest and provider wrapper over audited TRAIN captures, using tiny synthetic fixtures. The artifact must contain parent execution/capture hashes, selected anchor IDs, deterministic seed, policy version, masks and support counts, selection order, and complete rejection accounting. It must be immutable and independently auditable, with its hash in source metadata. Both lanes receive identical selected rounds. This is a new run, not an exact resume of the live run.

Select whole rounds, retaining their entire valid recurrent chain and accepted feature root. Unsupported positions can still carry state and gradients to later supported losses; removing them is incorrect. Two rows with the same label prefix need not be interchangeable: their student states, depths and context roots may differ. Redundant labels allow teacher reuse, not automatic deletion of recurrent training states.

Start with source/category/language, prompt-length, generation-position and supervision-depth quotas, then greedy marginal coverage per declared cost. Coverage cells can include supported absolute target IDs and coarse label-frequency bins, with bounded rare-label preference. Preserve common labels and some later rounds from every represented prompt family. Count unsupported labels in denominators; never remap them or modify the frozen vocabulary. A supported-label histogram alone cannot measure predictive probability mass because v2 contains no probabilities.

The cost proxy is accepted prefix length plus valid chain length, calibrated later against step timing. Report retained supported labels, unique exact label prefixes and sum of rebuilt prefix positions. If selection retains fraction `q` of rounds, it removes exactly `(1-q)` of round presentations at equal epochs, not necessarily that fraction of GPU time. A prefix-position budget supplies a better structural bound. Already captured teacher work is sunk; this deliverable saves training work only. Repeating the subset until the original step cap is reached can erase the saving.

Existing D rejection and proposed-token identities can identify supported early-depth mistakes, but cannot isolate A1 susceptibility. V2 supplies neither target entropy nor target margins. A later bounded paired TRAIN replay could score A8-correct/A1-wrong positions and persistent loss across checkpoints; its model cost must be charged. Prefer this concrete quantization gap to high loss alone, while retaining examples where both lanes succeed and where both fail.

Compare one selected subset with a stratified random subset at the same prefix-position budget, and with the frozen full-data control. Preserve per-round mean CE initially; inverse-frequency loss weights would be another intervention. Native development acceptance, including depth survival and per-domain outcomes, must improve or remain within a predeclared tolerance at lower total GPU hours. Charge selection overhead and report common supervised-token points. No sealed prompts enter scoring.

## Deliverable 2: byte-preserving indexed features

Prepare a new provider/storage schema referencing the retained raw F32 file plus selected native row indices instead of materializing `features.npy`. Keep a logical selected-feature ledger and reconstruction hash, raw file hash, tap order, feature boundary, absolute positions and source event ownership. Gather the same rows in the same order at the existing provider boundary. Validate byte-identical reconstruction with bounded fixtures before considering real train shards.

Each three-tap 7,680-wide F32 selected row occupies 30,720 bytes. For `S` selected rows, eliminating that additional array saves approximately `30,720*S` bytes, excluding metadata. Raw bytes remain preserved and their hardlinks must be counted once physically. Accepted rows are already unique within the current selected array, so no larger duplication factor is justified. This saves storage and preparation copying; it saves zero target inference and zero training arithmetic by itself. Scattered reads can worsen I/O, so bounded sequential gathers and measured loader throughput are the later gate. F16 or lossy feature compression is a different numerical experiment and is deferred. New KL recipes need correctly scoped probability/logit artifacts, reused if available or freshly captured; hard labels cannot reconstruct distributions.

## Deliverable 3: choose future teacher requests before capture

Build a TRAIN-only prompt-ID chooser that balances the existing source and length strata, spreads hashed n-gram coverage, and estimates capture cost from frozen input lengths and generation caps. It emits a new hashed selection manifest; it does not relabel existing shards or promote the reserve silently. Do not optimize similarity to the 24 development prompts, which would narrow coverage around the evaluation set.

For refresh, join the existing normalized teacher index before issuing requests. Reuse only exact complete token prefixes with matching target, tokenizer, sampler, native execution scope, mapping and feature taps. Feature ancestry is checked independently; matching a label does not supply missing accepted-root features. A changed student token needs a fresh label, and a new architecture requiring different target taps needs new features. Rebuilt student states and K/V are never teacher artifacts to reuse across updates.

Selecting half the planned prompts bounds request-count reduction at 50% before fixed overhead; wall time depends on lengths and generated rounds. Existing exact-prefix hits save only their corresponding missing-work requests. Self-paced selection risks locking onto easy templates, while hard-only selection overweights unsupported or irreducible errors. Keep stratified exploration and a fixed full-data control. The two-day outcome is reviewable CPU machinery and explicit bounds, not a promised acceptance gain or a reason to interrupt the running experiment.
