# Batching and vectorized accepted-prefix cache construction

Audit date: 2026-10-01. Source checkout: `d725fc88d52fc49841c2b20128d176c1e7f486d8`. This is a source/primary-literature audit, not an implementation or a performance result. No tests, model workloads, accelerator operations, remote connections, large capture reads, or sealed-final access were performed. The continuous A8/A1 pipeline remains frozen.

## Verdict

**Prioritize a vectorized, K/V-only accepted-prefix builder before general minibatching.** It removes known unnecessary work without changing the existing one-round AdamW update. The pinned single-layer EAGLE architecture makes the cache rows independent functions of shifted token embeddings and captured target features. Context attention is unnecessary; “faster causal prefill” solves more work than this trainer needs. Follow with a batched output head over the attached states of one teacher-forced proposal chain. Only then test small grouped-round minibatches as a separately declared optimizer experiment.

This is a training-efficiency opportunity, not evidence that W1A1 will recover acceptance or beat Q4_0. Neither published packing speedups nor operation counts establish a local RTX 5080 speedup.

## Current bottleneck and applicable architecture

`recurrent_rollout.py:35–87` reconstructs every context position in a Python loop under `no_grad`, passing each position's independently captured feature through `encode_feature` and `decode_context`. It keeps only `result.cache`; `result.pre_norm` is discarded. `native_step.py:483–487` delegates context decoding to the full step with only the head disabled. That full step still computes Q, attention, O, residual/norm, and three FFN projections (`native_step.py:392–467`), and appends K/V using two growing `torch.cat` operations (`435–438`). It also materializes fourfold GQA K/V expansion (`448–453`).

`recurrent_provider.py:249–271` performs this reconstruction before each proposal chain. `continuous_qat.py:788–885` repeats it separately for A8 and A1, then updates each lane's independent optimizer. No student-cache value can be shared between these lanes. The streaming provider retains the first model-loading shard and one active shard; its iterator preserves shard/prompt/round presentation order (`scripts/w1ax_multishard_provider.py:246–358`). `AuditedCapture.round_inputs` copies a full F32 accepted-feature prefix for each round by exact `(prompt_id, accepted_token_prefix)` joins (`scripts/audit_recurrent_binary_capture.py:364–382`). Overlapping rounds therefore repeat input copying and student reconstruction.

The single-layer condition is explicit in native `third_party/llama.cpp/src/models/eagle3.cpp:415`. Its existing `eagle3_kv_only` graph already omits Q and returns after K/V writes, guarded by one layer, zero requested outputs, and disabled embeddings (`486–487`, `517–564`). This confirms architectural applicability; it does not benchmark the Torch trainer.

Historical row-A16 calibration measured 100 rounds/495 supported labels/9,393 feature joins, mean synchronized total step 0.923 s and median 0.737 s, with peak allocated/reserved 8.494/10.049 GiB. These timings include transfer, reconstruction, unroll, backward, and optimizer; they contain no prefix-stage attribution and are not A8/A1 results. See [calibration](../w1ax-row-a16-calibration-5080.md).

## Exact cache derivation and contracts

Let accepted tokens be `t[0:P+1]`, seed `t[P+1]`, and captured raw target-feature rows `H[0:P+1]`. For each **context** position `j < P`:

1. `g_j = FC_theta(H_j)`; FC uses the current lane's hard W1Ax parameters.
2. Borrow frozen F16 embedding `E[t[j+1]]`, cast to F32, and concatenate **embedding norm first**, feature norm second: `z_j = cat(RMS_emb(E), RMS_feature(g_j))`.
3. `K_j = F32(F16(RoPE_j(Kproj_theta(z_j))))`; `V_j = F32(F16(Vproj_theta(z_j)))`.
4. Stack to `(8, P, 128)`, retaining exactly the cache order `0..P-1`.

No `Q_j`, attention result, or FFN result appears in these formulas. `g_(j+1)` comes from captured `H_(j+1)`, not the discarded `pre_norm_j`. Thus FC, norms, K/V, and K-RoPE can operate on `[P, width]` in bulk or bounded chunks, without an attention mask. This would fail for additional decoder layers whose later-layer K/V consume earlier-layer attention/FFN states, or if a caller consumed context outputs. Restrict the optimization explicitly to the pinned single-layer/no-consumed-output contract.

The deferred row **must remain separate**: the seed uses `FC_theta(H_P)` with gradients at decoder/RoPE position `P`, input token `t[P+1]`. Proposal depth `d` uses decoder position `P+d`; its input token follows the previous **captured proposal**, even when the native verifier label differs. Its feature is the previous student's attached **pre-norm** state, never a cached normalized head state or a fresh accepted target feature. Each step appends F16-rounded current K/V before attention. An invalid row is terminal, gets no label/proposal/cache append, and cannot have a child. Unsupported but valid labels have no direct hard-CE loss but must execute the recurrent state/K/V path to supported descendants. `recurrent_trace.py` validates these conditions, the draft-to-target offset map, and independent round anchors.

All context-cache construction stays under `no_grad`; proposal states/K/V retain autograd, including the F16→F32 boundary casts. Bulk context must not accidentally train FC/K/V through accepted history. Conversely, do not obtain the seed by slicing a no-gradient FC result. A context row needed by another round and a seed row needed with gradients require distinct graph treatment.

Quantization/RMS reductions are over the final feature dimension **per token**, never over a batch, pack, or prefix. Preserve A8 signed absmax, nearest-even rounding, zero-scale behavior, and A1 raw-bit sign conventions/mean-absolute scaling. Keep frozen embeddings/norms/map, no autocast, and the pinned F32/TF32 policy. CPU RoPE frequencies currently use repeated F32 multiplication independently from each position; CUDA uses the declared power-based surrogate. A bulk frequency table must reproduce the selected backend formula, half-rotation ordering, and absolute decoder positions. GEMV→GEMM can change accumulation and F16 rounding; this is a bounded numeric/trajectory question, not a reason to require global bitwise backend parity.

## Ranked algorithms

| Rank | Algorithm | Defensible savings | Complexity and decision |
|---|---|---|---|
| 1 | K/V-only bulk/chunked context, B=1 | Removes five unused body projections, context attention, growing cache copies, and most per-position launches | Moderate; preserves loss, round order, update cadence, and truncation boundary. First candidate. Chunking bounds peak memory. |
| 2 | Batch one round's output norm/head after recurrent unroll | Same head MACs for supervised rows; up to five head GEMVs become one small GEMM, and unsupported direct heads can be omitted | Low/moderate. Captured token choices do not depend on current logits. Store attached pre-norm states, then compute the unchanged masked CE. Do not parallelize recurrent depths themselves. |
| 3 | Group independent rounds, advance active chains depth-by-depth; length buckets and token caps | Larger body/head GEMMs, one optimizer scan per batch, fewer launches | Moderate/high; changes AdamW cadence and sample weighting unless explicitly specified. Try B=2 then B=4 with measured admission, after ranks 1–2. |
| 4 | Share exact overlapping context within one frozen lane/update | Reduces repeated context rows from `sum P_i` toward unique shifted-token/feature/position rows; nested same-prompt prefixes can approach `max P_i` | Moderate; only within a declared minibatch/evaluation snapshot. Validate feature ancestry and shift token, keep independent proposal caches, and invalidate after every update. |
| 5 | Ragged/packed proposal attention | Avoids padded K/V and attention work in variable-length grouped rounds | High; only if padded batched attention becomes material. There is no baseline padding waste at B=1. Dense block masking over a concatenated pack computes needless cross-example scores. |
| Defer | Full causal vectorized context prefill | Eliminates Python serial execution but still computes outputs nobody consumes | Inferior to rank 1 for this architecture; useful only if the output contract changes. |

For grouped rounds, batch row-local linears across active examples at each depth; each example still has its own previous state and K/V. A simple padded `[B, Hq, 1, Smax]` attention path is a clearer first implementation than a new ragged framework. Explicit mask entries permit only that example's keys through position `P_i+d`. Zero-valued padding is not sufficient: unmasked pads change the softmax denominator. Pack offsets are storage offsets, not RoPE positions. Never allow sibling, other-round, other-prompt, future, or invalid rows into attention.

For a single query against an already appended prefix, use all valid keys, with explicit padding mask and `is_causal=False`. PyTorch SDPA's non-square `is_causal=True` uses upper-left alignment, whereas FlashAttention documents bottom-right alignment; silently switching interfaces can hide most of the prefix. [PyTorch source](https://raw.githubusercontent.com/pytorch/pytorch/main/torch/nn/functional.py), [FlashAttention source](https://github.com/Dao-AILab/flash-attention).

`vmap` does not automatically solve variable cache lengths: its mapped outputs must have common shapes. Manual batched linears plus explicit lengths are more transparent here. [PyTorch limitations](https://docs.pytorch.org/docs/2.14/func.ux_limitations.html).

## Bounds, optimizer changes, and memory

From the pinned shapes, one context row currently executes **136,314,880 linear MACs**: FC 19,660,800; Q 20,971,520; K+V 10,485,760; O 10,485,760; FFN 74,711,040. K/V-only needs **30,146,560**, removing **106,168,320 / 77.88%** of these MACs. The vocabulary head is already omitted for context. These are logical dot-product counts for one pass, not elapsed-time predictions; A1 currently performs both surrogate and native F.linear paths, an independent optimization owned by the kernel audit.

Context QK and AV additionally execute approximately `2*(32*128)*P*(P+1)/2` MACs, all removable. Growing cache concatenations write `8192*P*(P+1)/2` output bytes versus `8192*P` final cache bytes, excluding reads/allocator overhead. At `P=2046`—the configured 2048-token prefix cap includes two shifted/deferred token entries—this is about **16 GiB of cumulative cache-output writes** to produce a final ~16 MiB F32 cache. No GPU timing is implied. If measured prefix reconstruction occupies fraction `f` of step time and its measured speed ratio is `r`, whole-step ratio is `1/[(1-f)+f/r]`; first measure `f`.

Minibatching is not an algebraically exact replacement for sequential AdamW updates: moments, clipping, projected latent/scales, warmup, and intervening changed forward parameters differ. Even averaging gradients at one snapshot cannot recreate the original updates. Keep minibatch recipe and source hashes separate from exact-resume runs. Do not silently multiply learning rates or reuse caches across updates merely because signs did not flip; FC/K/V scales and activation signs can change. Sharing A8/A1 raw captured tensors or frozen embeddings is safe; sharing their student caches/hard signs/graphs is not.

An attached hard-sign tensor can serve one combined forward/backward group; rebuild it for separate microbatch backward calls, as the existing context manager forbids graph reuse across backward. Detached no-gradient context values may be shared within the same frozen update snapshot. Preserve diagnostic meaning too: `last_saturation_fraction` is currently the last projection call's statistic; a batched head naturally reports an aggregate, which must be labeled or reconstructed per depth rather than silently equated.

Choose loss weighting deliberately. Presently each round's loss is mean CE over its `n_i` supported valid tokens. Equal-round batch weighting is `mean_i(sum CE_i/n_i)`; token weighting is `sum_i,sum_j CE_ij / sum_i n_i`. The latter gives longer supported chains more weight. For gradient accumulation, use the global supervised-token denominator, not an average of unequal microbatch means. Skip zero-supported rounds as currently; keep unsupported valid tokens in quality denominators. Report supervised tokens, unique rows/prompts, optimizer updates, contexts rebuilt, and wall time separately. Grouping same-prompt nested rounds maximizes sharing but correlates examples; length sorting may change domain/order distribution. A deterministic bounded buffer within the current shard, with recorded source IDs and exact-resume buffer state, is preferable to unrestricted corpus sorting.

Persistent dual-lane parameters/Adam moments/shared F16 embedding already total ~5.61 GiB, with ~0.813 GiB active gradients, before hard signs, graph, caches, and allocator temporaries. At ~2048 rows raw F32 features alone are ~60 MiB/example; final F32 K/V ~16 MiB, GQA-expanded pair ~64 MiB. Bulk FC/fused intermediates add tens of MiB; chunks can release them before the next chunk. Proposal autograd and shared hard-sign buffers, rather than the small final cache alone, can dominate. Do not scale the assumed 3 GiB graph budget linearly and declare fit. Keep A8 then A1 with one live graph; preserve ≤12 GiB reserved/≥1 GiB free admission and host floors. Infer no 5080 capacity from an A100 paper.

## Smallest decisive gates and stopping rules

**Future CPU contract test, no model weights required:** extend existing tiny recurrent fixtures for A1/A8 and prefixes P=0,1, mixed short lengths; compare serial context with K/V-only chunk sizes 1/2/all. Require identical shifted tokens/positions, correct F16-exact cache storage, and chosen well-separated fixtures' equal cache values. Instrument Q/O/FFN/head to fail if called by the prefix builder. Verify seed FC is attached, context is detached, and later-only CE reaches the first proposal state/K/V. Compare stacked-head logits/loss/18 parameter gradients and one optimizer update with the serial-head reference, within predeclared F32 tolerances. Include unsupported-first/supported-later and terminal-invalid cases. Two grouped examples with different tokens/features/lengths must match separate same-snapshot forwards; perturbing one example must not change the other's logits or gradients. Reject incorrect map/anchor/source hashes, padded/future leakage, malformed offsets, and stale lane/update cache keys. Test the chosen unequal-token loss normalization explicitly.

**Future CUDA microbenchmark:** first profile frozen B=1 baseline vs K/V-only vs K/V-only+stacked-head on A8 and A1 separately, using actual audited train rounds and bounded synthetic shape probes P≈64/256/1024/2046, depth1/5. Warm before timing; record prefix, proposal, backward, optimizer, transfers, full-pair time, peak allocated/reserved, and useful supervised tokens/sec. Then B=2/4 length-bucketed experiments under the same memory floors. Keep parameters/order/update cadence identical for rank1/2 and exclude cold compilation/startup from warmed medians while reporting cold cost separately. Stop at the first memory/ancestry/gradient failure; do not expand a ragged implementation absent measured padding/attention waste.

Apply the existing practical export gate (relative RMS≤0.10, no changed native choice with margin>0.02, record lower-margin flips) on representative unsealed train roots, plus exact ancestry/masks and attached later gradients. For rank1/2, additionally compare with the current Torch reference to catch avoidable drift before export. Do not spend an open-ended parity effort on benign accumulation changes.

**Future equal-GPU-hour quality gate:** after admission, predeclare a bounded common GPU-hour budget and dev schedule for current vs optimized B=1; compare same-token snapshots as well as time-limited outcomes. B=2/4 is a separate optimizer arm, with fixed initialization, both precisions, paired data domains, explicit token/round weighting, update/token counters, and no automatic LR scaling. Native acceptance on the fixed independent dev prompts is the deciding quality signal; teacher-forced CE alone is insufficient. Adopt a larger batch only if its faster presentations produce noninferior native acceptance at equal GPU hours, with repeated-seed/paired-prompt uncertainty reported. Include Q4_0 as the primary acceptance/latency/complete-throughput benchmark and FP16 as diagnostic; no sealed-final selection or inference-speed claim follows from a faster trainer.
