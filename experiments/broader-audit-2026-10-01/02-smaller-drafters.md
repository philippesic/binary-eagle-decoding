# Smaller EAGLE drafters: remove dimensions, not just bits

Date: 2026-10-01. Source: `f0bb92dda687d908b3cffe084510b3be757df54f`. This is a static applicability audit. No model, accelerator, remote, training or acceptance runs occurred; no large weights, captures or sealed-final prompts were read. Qwen3-4B target/verifier and original EAGLE recurrence remain the boundary. Recommendations need user selection before a new architecture experiment.

## Verdict and cost geometry

Structural compression deserves a bounded screen after the current quality phase. Within the drafter body, rank **coupled FFN neuron removal first, factorized feature fusion second, and whole attention-head pruning third**. The separately audited factorized head has larger upside. Avoid shrinking the residual stream first. Smaller parameter count is insufficient: representation quality, executed precision, added launches and native prefix survival decide success.

The pinned nine matrices contain 218,234,880 parameters: head 81.92M, FFN 74.71M, attention 41.94M, fusion 19.66M. Their strict one-bit signs still occupy 26.02 MiB before scales; the head alone is 9.77 MiB. Low bits do not eliminate reading these weights repeatedly, activation packing, output scoring, or sequential recurrent steps. Attention/cache/norm/SiLU/residual operations remain wider. Training still uses dense latent tensors, optimizer states and surrogate products. Source counts are in `experiments/drafter-static-coverage.md`; they are parameter/MAC budgets, not measured SM75 speed predictions.

EAGLE already has one decoder layer, so depth reduction offers almost nothing. [Decoding Speculative Decoding](https://aclanthology.org/2025.naacl-long.328/) found that a wider, shallower standalone drafter reduced latency 49% and improved throughput 41% despite lower acceptance than its deep counterpart; the construction used substantial pruning data. Its observation that language-model accuracy poorly predicts drafting performance supports native acceptance gates, but its depth recipe does not transfer to this one-layer auxiliary drafter.

## Head comparison: coordinate with the output-head audit

Replacing the 32,000×2,560 head by 2,560→r→32,000 at r=256/512 leaves 8.85M/17.69M parameters, preserves current vocabulary support and the full residual interface. [SlimSpec](https://arxiv.org/html/2605.10453v1) supplies direct trained EAGLE-3 precedent on H200/vLLM, not zero-shot W1Ax evidence. The crucial storage trap: F16 factors occupy 16.88/33.75 MiB, **more than the current strict-W1 head's 9.77 MiB**. They can save bandwidth against Q4_0 while losing against W1. Binary factors add an activation quantization boundary; wider factors are mixed precision. A low-rank residual added to the original head preserves its large read and adds work. The output-head audit owns the detailed candidate and training review.

## 1. Coupled FFN neuron removal: cleanest geometry change

The SwiGLU hidden width is 9,728. Remove the same neuron indices from gate/up rows and down columns; retain their order. Width 7,296 removes 18.68M parameters/MACs, or 8.56% of all selected parameters. Width 6,144 removes 27.53M, or 12.61%. Both are multiples of 128 and retain the 2,560-dimensional residual/norm/head/embedding interface. Whole neurons yield compact dense matrices; setting arbitrary weights to zero does not yield this execution benefit.

[LLM-Pruner and author implementation](https://github.com/horseee/LLM-Pruner) demonstrate dependency-aware pruning and recovery, support GQA, and permit CPU Taylor importance estimation. Their approximately 20%-pruned LLaMA example reports 1.18× latency speedup after recovery, with task accuracy below the original. [SlimGPT](https://arxiv.org/html/2412.18110v1) supplies an alternative second-order, calibration-based structured pruning method. Neither establishes speculative prefix acceptance or binary FFN tolerance. SparseGPT-style unstructured sparsity is a weaker fit because the existing packed-dense binary operator does not skip arbitrary zeros.

Later CPU screening should score actual post-SiLU gate×up neuron contributions to the down output on a fixed train-side capture slice, supplemented by a small recurrent sensitivity check. Raw binary weight magnitude is especially uninformative when each row shares one scale; down-column norm alone ignores gating frequency and cancellation. Fit retained down weights or row scales only as a declared recovery stage, using the deployed quantizer. Re-estimate scale groups after column removal: old 128-column boundaries no longer identify the same channels. For A1/A4/A8, pruning also changes token meanabs scales and codes, so neuron slicing is not an exact numerical transformation.

Start with the 25% FFN removal, not simultaneous attention/fusion/head surgery. It reduces activation/latent/optimizer storage as well as inference dimensions. Its maximum arithmetic benefit is modest, and after K/V-only context construction the context path has no FFN to accelerate. This avoids double-counting the earlier training audit's unused-context elimination.

## 2. Feature fusion: easy boundary, higher quality risk

Factor the 7,680→2,560 fusion into 7,680→512→2,560. This uses 5.24M parameters/MACs instead of 19.66M, saving 14.42M or 6.61% of selected parameters. Keep tap order [2,18,33], input width, optional normalization, output width and recurrent-state meaning. The graph gains a projection and intermediate buffer, so component savings must include both launches and packing.

[SVD-LLM and author implementation](https://github.com/AIoT-MLSys-Lab/SVD-LLM) use activation whitening and closed-form reconstruction rather than assuming weight singular values predict output error. The [paper](https://arxiv.org/html/2403.07378v3) combines factorization with GPTQ-4bit, reporting smaller memory and lower perplexity than GPTQ-3bit; it also measures A100/CPU speedups. These are useful low-bit compatibility precedents, not W1Ax or acceptance results. A full 7,680² F32 covariance alone is 225 MiB; bounded diagonal/low-rank calibration may be a cheaper first screen, with its approximation disclosed.

Fusion and attention are locally sensitive. The completed attention+fusion Q8_0 rescue still achieved only 0.616× Q4_0 client throughput on RTX 5080; dense-head interventions traced much deterioration to the binary body and later recurrence (`experiments/binary-rescue-head-5080.md`). This does not condemn narrower learned models, but it makes untrained fusion truncation a poor default and prevents calling wider factors a proven cure.

Weight-only truncated SVD is an inexpensive initialization hypothesis, not an acceptance predictor. Fit a bounded train-side native feature sample, preserve its three-tap ancestry and check reconstruction on a distinct train-side slice before native development evaluation. Insert no new norm/nonlinearity between factors when diagnosing ordinary low-rank reconstruction; binarizing the intermediate adds a separate information-loss mechanism. Compare factorization at original precision before quantized factors so those two losses are distinguishable. Frozen-target distillation may teach a compact fusion, but new dense factors require exporter and trainer allowlist changes.

## 3. Attention heads: preserve RoPE pairs and GQA groups

A narrower first attention option retains all eight K/V heads and removes two of four query heads per KV group, uniformly. Q changes from 32 to 16 whole 128-dimensional heads; remove matching O columns. This saves 15.73M parameters/MACs, 7.21% of selected total, without changing cache dimensions or K/V prefix-construction work. The output remains 2,560-wide. Retained K/V geometry is unchanged, but later recurrent values can change because O outputs change.

Removing two complete KV groups instead removes their eight associated query heads and matching O columns, saving 10.49M projection parameters and 25% draft KV storage. Preserve Q/K pair rotations, group order, absolute positions, head dimension, frequencies and F16 cache writes. Arbitrary head-channel slicing corrupts pair geometry; head-count metadata and native cache allocation must match the new tensors. Native diagnostics hard-code the original geometry, so their applicability must be revised explicitly. This is a conditional third screen after body profiling shows attention cost; the rescue evidence argues against zero-shot confidence.

## Deferred geometry and decisive gates

Residual-width shrinking changes borrowed target embeddings, all norms, fusion, residual additions and the recurrence contract. Native code distinguishes target feature width, but the Torch reference assumes `fc=(hidden,3*hidden)` and a borrowed embedding of that same hidden width. SliceGPT's rotation/slicing machinery and [author code](https://github.com/microsoft/TransformerCompression) are not a drop-in fix for these frozen external boundaries. A small distilled EAGLE student with embedding adapters is a later new architecture decision, not a two-day pruning patch.

The smallest GPU-free two-day deliverable is a candidate shape/export plan and fixed train-capture selection/ancestry manifest for FFN width 7,296, with bounded CPU fitting/sensitivity specifications; fusion rank 512 is the reserve. This audit supplies the plan; it does not authorize those model workloads. Later, run an untrained native development-chain comparison first; if necessary allow one predeclared short fine-tune on existing native labels/features. Reject invalid cache/mask/export behavior, systematic rank/depth collapse, or an optimistic complete-round bound that cannot beat Q4_0. Final admission requires same-device Q4_0 acceptance, latency and throughput comparisons; CPU/Metal and 5080 do not certify SM75.

The idea is to remove whole neurons or replace one large projection with two smaller ones while retaining EAGLE's recurrent interface. This can reduce training memory and actual draft work beyond lowering bit width. FFN pruning is easiest to integrate, while a factorized head has the largest upside and direct EAGLE evidence. We can prepare exact shapes, export requirements and a bounded train-capture screen while the GPU is busy. Later, one native acceptance screen and one short recovery attempt should decide whether the smaller drafter can compete with Q4_0 before investing in kernels.
