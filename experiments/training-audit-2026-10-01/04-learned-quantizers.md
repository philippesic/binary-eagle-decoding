# Learned activation quantizers: conditional quality opportunity

Audit date: 2026-10-01. Read-only implementation review at parent source revision `d725fc88d52fc49841c2b20128d176c1e7f486d8`; no tests, model workloads, accelerator/remote actions, weights, large datasets, or sealed sets were accessed. This report is a proposal for a separately approved experiment. The fixed continuous A8/A1 pipeline remains unchanged. Q4_0 EAGLE is the primary deployment comparator; FP16 is diagnostic.

## Verdict and shortlist

**Conditional pursue**, primarily for quality per training token, not a demonstrated training-speed improvement. Learned quantizers add little parameter memory but additional activation operations/reductions; their speed value would have to come from faster quality recovery. Do not promise cheaper training steps.

1. **First narrow candidate: A4 symmetric relative step/clipping**, one learned dimensionless scalar per shared input boundary, initialized to preserve the current quantizer. It can recover resolution lost to absmax outliers without changing integer-dot arithmetic or code layout. A8 is a useful lower-risk transfer check, but existing evidence gives A4 more headroom. Both still require a new packing/export contract.
2. **W1A1-specific candidate: learned activation threshold**, initially one scalar per shared boundary, retaining per-token meanabs amplitude. It changes the binary decisions that an amplitude-only experiment cannot. Escalate to per-input-channel thresholds only after the scalar screen; channel thresholds still fit one-bit packing but are a larger optimization choice.
3. **Defer positive A1 amplitude multipliers alone**, especially at the head: they are redundant with learned row scales and cannot directly repair exact-real greedy head ranking. A learned *constant replacing* dynamic meanabs is a different experiment, with possible body effects, but removes token-amplitude information and needs a new runtime scale rule.
4. **Defer LSQ+ offsets, unsigned two-set binarization, channel amplitudes, and block amplitudes** until a measured signed-distribution/error mechanism justifies the added contract and kernel work.

## What the current source actually does

[recurrent_qat.py](/Users/pippo/github/binary-eagle-decoding/src/w1a1_eagle/recurrent_qat.py:60) casts activations to F32. A8/A4 use a complete-token absmax `M`, scale `s=M/127` or `M/7`, codes `round_even(x*(qmax/M))` clamped to symmetric `[-127,127]` or `[-7,7]`. The most-negative two's-complement code is unused. An all-zero token has scale and codes zero. The reported saturation mask means “endpoint code”; it is not evidence of actual clipping. Dynamic scales and the mask are nondifferentiable; the backward is **identity through dequantized values everywhere**, including endpoints and zero vectors. A16 uses an explicit F16 boundary cast and cast derivative.

A1 uses `mean(abs(x))`, accumulated in F64 and rounded to F32, with two reconstruction levels ±scale. Signed zeros are positive; zero vectors have positive sign bits but zero reconstructed values. The corrected row-linear A1 forward uses raw-bit sign selection, preserving negative subnormal signs, then an exact F32 ±1 dot at deployed widths, then row scale, then token scale. Its gradient remains the original dequantized-value STE; it does not differentiate the native correction or dynamic meanabs. This is intentional forward/backward separation, not ordinary differentiation of `scale*sign(x)`.

All nine linears train latent signs and nonnegative **weight row scales**, initialized from original dense signs and meanabs row scales. There is currently no learned activation parameter. Latents start at ±0.5; sign STE is identity for `abs(latent)<=1`. Additive weight-scale offsets use `where(raw>=0,raw,0)` and post-update projection, retaining derivative one at exact zero. [native_step.py](/Users/pippo/github/binary-eagle-decoding/src/w1a1_eagle/native_step.py:257) freezes every parameter outside the sign/weight-scale pairs; adding activation parameters requires updating this allowlist and optimizer/checkpoint/resume audits, not just defining a parameter.

[w1a1.cu](/Users/pippo/github/binary-eagle-decoding/third_party/llama.cpp/ggml/src/ggml-cuda/w1a1.cu:13) implements the same A1 packing and A4/A8 absmax rule. The dot epilogue is `(integer_dot*row_scale)*token_scale`. A4 uses four signed bit planes or conventional codes; threshold changes do not inherently change plane layout. [The exporter](/Users/pippo/github/binary-eagle-decoding/scripts/export_recurrent_binary.py:80) accepts exactly the existing activation-rule string, with no activation parameters. A new quantizer is not currently exportable.

[Native shared packing](/Users/pippo/github/binary-eagle-decoding/third_party/llama.cpp/src/models/eagle3.cpp:419) keys by input tensor identity, assuming one quantizer for every consumer. Q/K/V and gate/up should therefore share quantizer parameters. Separate consumer quantizers require the cache key to include their contract/parameter identity or separate packs. Six natural boundaries are fusion, QKV input, attention-output input, gate/up input, down input, and head input.

The historical [SM75 activation report](/Users/pippo/github/binary-eagle-decoding/experiments/w1ax-activation-precision-results.md:233) found A4 zero-code rates of 98.31% at fusion and 88.88% at FFN-down, while clipping was zero. In 145 correlated head rows, top-1 agreement with same-binary-weight A16 was A8 97.2%, A4 72.4%, A1 33.1%. These support a bounded resolution/threshold hypothesis, not causal attribution: A16 itself still had severe acceptance loss, so activation quantizers cannot be assumed to solve binary-weight/recurrent quality failure.

## What a positive beta can and cannot change

For a fixed input token with signs `b_i=sign(x_i)`, let `d_r=sum_i sign(W_ri)b_i`. The bias-free A1 head produces

`z_r = beta(x) * alpha_r * d_r`.

For any strictly positive common beta, `argmax_r z_r = argmax_r alpha_r*d_r`. It changes softmax temperature, CE, sampling probabilities, confidence cutoffs, and potentially scores accumulated across different tree contexts. It cannot directly change within-token head rank. At beta zero every output ties; finite arithmetic can introduce underflow/rounding exceptions, which are not useful representational gains.

Two distinctions prevent misleading experiments:

- Learning `c>0` in `beta(x)=c*meanabs(x)` adds no exact-real capacity: absorb `c` into all learned `alpha_r`. Likewise, positive prescaling followed by any current homogeneous dynamic quantizer satisfies `Q(c*x)=c*Q(x)`. Folding changes floating operation order, so it still needs the practical native gate.
- Replacing dynamic meanabs with one learned constant removes token-dependent amplitude. It cannot fix head ranks at fixed weights, but earlier projections can change residual ratios, QK softmax temperature, SiLU gating, and F16 cache values. Conversely, RMS normalization and later A1 signs can remove uniform amplitude effects in some paths. This is a distinct scale-rule ablation, not proof that an amplitude multiplier adds capacity.

Earlier projection amplitudes matter *relative to other branches and tokens*; there is no general end-to-end scale invariance. Nevertheless, their learned row scales already provide a per-projection amplitude degree of freedom. A redundant global multiplier can change optimization conditioning, not the representable family.

Learning `sign(x-t)` changes the partition of inputs into bits. It can split examples that shared the old sign code or move important features across a decision boundary; it still preserves only one bit per feature and cannot recover arbitrary magnitudes. Sign entropy alone is not a quality objective: balanced bits can discard useful zero/rare-feature semantics.

## Small parameterizations and deployment costs

For A4/A8, propose `s_ref=detach(absmax(x)/qmax)`, `s=c*s_ref`, `q=round_even(clamp(x/s,-qmax,qmax))`, `Q=s*q`. Initialize `c=1`; this reproduces current forward. Lower c yields finer resolution and deliberate clipping; higher c yields coarser codes. Putting c only *after* unchanged codes is merely amplitude calibration. Static learned `s` is also deployable with unchanged integer-dot math, but removes token adaptation and risks recurrent/context distribution shift. Compare calibrated fixed c before assuming learning is necessary.

For A1, a minimal threshold is `t=delta*detach(meanabs(x))`, with delta initialized zero and retained dynamic meanabs amplitude. Scalar delta per boundary preserves sharing; a vector delta per input channel offers more flexibility while still producing ordinary sign words. New pack logic and versioned parameter metadata suffice; no new dot epilogue is needed for reconstruction `±meanabs(x)`. Specify tie-positive comparisons and raw-subnormal behavior explicitly.

LSQ+ reconstruction `Q=s*q+o` adds `alpha_r*o*sum_i sign(W_ri)` to each output. A static scalar offset allows precomputing this row correction at export, but the current packed path has no correction tensor/epilogue. Channel offsets need `alpha_r*sum_i sign(W_ri)*o_i`. Thresholding without reconstructing the offset has no such term. Unsigned `{0,s}` binaries similarly need `(signed_dot+weight_sign_row_sum)/2`; ordinary XOR-dot output alone is incorrect.

Per-channel activation **thresholds** retain one-bit dot compatibility. Per-channel **amplitudes/steps** put nonuniform factors inside the reduction and cannot use one token scale after the dot. Block amplitudes require block partial dots plus weighted accumulation and metadata; current group128 supports A16 only. These are runtime projects, not tiny quantizer edits.

## Gradient, initialization, and failure modes

For signed uniform LSQ, the interior step surrogate is `dQ/ds=q-x/s`; outside the range it is the corresponding endpoint. Input STE is one inside the unclipped interval and zero outside. This differs from the current unconditional identity activation STE. A two-arm comparison that changes both must attribute its result to the *whole quantizer recipe*, not scale learning alone; a frozen-scale control with the same input STE is the smallest follow-up if it wins.

Define normalization by the number of valid features contributing to each shared parameter and qmax, with loss reduction and unroll sharing explicit. Do not count padded/masked rows or normalize per consumer when QKV shares one quantizer. Paper heuristics were not derived for this recurrent mean-reduced loss/AdamW/global clipping setting. Adam largely cancels constant gradient scaling through its moments; epsilon, transients and global norm clipping prevent exact cancellation. Track actual relative parameter updates and whether the added quantizer gradients crowd out sign gradients.

Use positive parameterization with a lower floor, or projected nonnegative additive steps with a documented zero derivative; no weight decay. `s=0` causes divide-by-zero, all-zero code collapse, or dead parameters. A hard floor can kill recovery gradients below it; softplus/log scales avoid negative steps but can make near-zero recovery slow. Keep zero input tokens an explicit zero-output branch; an epsilon divisor must not invent nonzero activation magnitude. Start A4/A8 at current c=1 or train-only MSE calibration; start A1 threshold at zero. Normalize thresholds by detached dynamic scale so one learning rate has a sensible meaning across boundaries. Monitor clipping **of x**, zero-code rate, near-threshold density, sign changes, gradient norms, scale ratios, per-depth native agreement, and online acceptance. Endpoints and saturation alone are insufficient.

Scalar parameter/moment storage is negligible; threshold vectors are small relative to 218M latent weights. Additional elementwise work and reductions still touch large unroll activations. Measure step latency and peak memory; do not infer speed from parameter count.

## Smallest future comparison and deployment gate

Authorize one separate two-arm screen, not a Cartesian sweep. For A4: baseline current absmax versus six-boundary relative learned-step recipe. For A1: baseline versus six-boundary normalized threshold recipe. Use the same original row-weight initialization, native train prefixes/features/labels, supported masks, examples and supervised-token budget, sign/row-scale optimizer, unroll depth, and seed. Predeclare one modest token budget and an equal wall-time cap; report both axes because slower learned steps consume fewer tokens under the cap. Include calibration time in cost. Use fixed checkpoint positions and the existing development pool for selection; never the sealed finals. Repeat a winning comparison with a second seed before interpreting small gains.

First gate: parameter ownership and later state/K/V gradients; finite gradients and zero-token behavior; exact A4/A8 codes/integer dots or A1 packed bits, tail masks, ties and negative subnormals. Then export round-trip with a new activation-rule/schema, audited metadata and parameter hashes, Q/K row permutation preserved, and CPU/CUDA pack consistency. Bound native state/logit RMS and decision differences using the existing practical gate (relative RMS ≤0.10; no changed native choice with margin >0.02); record low-margin differences and investigate changes that alter training conclusions. Keep native A1 integer-dot → row-scale → token-scale order.

Finally evaluate native current-student rollouts: accepted tokens/round, prefix survival by depth, proposal count, teacher-forced CE, and packing-inclusive latency. Require a clear development acceptance gain over its same-width baseline without losing that gain to pack/launch cost. Only then run a matched RTX 2080 Ti end-to-end comparison against Q4_0 with fixed target/verifier and hardware/precision declared. Torch simulation quality, BERT accuracy, and CPU correctness cannot validate SM75 throughput.

## Alternatives worth bounding first

Train-only fixed clipping calibration is cheaper and reveals whether task learning is necessary. Channel outlier smoothing needs explicit binary-column representability analysis before use. Small activation blocks target fusion/down zeroing directly, but impose a new partial-dot/scaling kernel. Mixed activation precision at a sensitive boundary may buy more quality than learning a poor one-bit representation; report honest coverage and compare total cost. Preserve these as alternatives rather than silently changing the active A8/A1 lanes.
