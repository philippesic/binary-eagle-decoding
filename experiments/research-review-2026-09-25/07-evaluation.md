# Evaluation rigor, ceilings, and a bounded experiment portfolio

Local-only audit, 2026-09-25. Read against parent `7ae1cc2e4e5ce5f1e3070377722d679d15bc486e` and llama.cpp `34e21b7d85c17e25d5a91ce2ab1074d4c18bfe39`. No web research, model runs, GPU access, repository edits, or new final-set evaluation. Raw benchmark files are preserved remotely; this audit used committed reports and local analysis/runtime code, not an independent recomputation of remote raw data. Recommendations below are prospective, not measurements or amendments to the active goal.

## Main judgment

The evidence supports completing the already requested W1Ax study, making its first product a reliable quality/cost decomposition, and then trying one target-aligned QAT recipe. It does not support another open-ended binary-MMA optimization campaign. Current all-nine W1A1 needs nearly twice its measured throughput to catch the directly paired Q4_0 anchor. Head-only needs 22.3% more throughput. A binary-MMA head implementation already tied the portable path within a narrow observed interval. The most valuable missing data are complete round timing, accepted-prefix survival at each depth, and aligned target-vocabulary coverage; these discriminate between recoverable arithmetic overhead, wasted execution, and a quality ceiling.

The active goal is the full W1Ax matrix, not QAT or alternative architectures. Complete/checkpoint it before proposing a new goal. If its implementation or diagnostic grid would expand beyond the bounded project, record a concrete amendment for the user rather than silently reducing the requested matrix. Sources: `docs/STATUS.md`, `docs/goals/w1ax-activation-precision-suite.md`, `docs/PROJECT_OVERVIEW.md`, `experiments/w1ax-activation-precision-plan.md`.

## What the existing evidence establishes

1. **A strong negative result for these untrained native W1A1 recipes.** In the nine-path RTX 2080 Ti FP16-target run, head W1A1 / ordinary decode rate was 0.907, interval 0.869–0.946; all-nine was 0.561, interval 0.511–0.617. Every tested group lost. Q4_0 / ordinary was 1.109, interval 1.081–1.135. The within-run head/Q4_0 and all/Q4_0 point ratios, calculated from pooled table rates, are 0.8176 and 0.5060. Their confidence intervals must be recomputed directly from paired records; dividing endpoints of the ordinary-relative intervals is not a valid paired interval. [Source: `experiments/rtx2080ti-quantization-suite.md:170`, especially tables at 185, 201, 218.]
2. **Poor acceptance defeats lower draft-call cost.** All-nine W1A1 reduced the logged `draft()` span from 6.471 to 3.558 ms/round, but accepted drafts fell from 1.168 to 0.055/round. Rounds rose 3,400→6,940 and pooled draft-call time rose 22.0→24.7 seconds. The extra rounds are measured; the isolated verifier cost is not. Head quality is better, but it still loses to both throughput anchors. [Same source; `experiments/rtx2080ti-synthesis.md`.]
3. **Kernel novelty is not a performance predictor.** Binary-MMA / portable head was 1.0017, interval 0.9973–1.0062. W8A8 MMA / DP4A was 0.821, and W4A4 MMA / vector 0.880, with same-format acceptance and text unchanged. The N=1 component diagnostics favor the default integer paths; N=37 diagnostics favor MMA for several large operators. This supports shape-sensitive investigation only when a measured workload contains enough of those shapes. It does not establish a universal Tensor Core disadvantage. [Source: synthesis; suite sections at 259, 402, 488.]
4. **W8A8 did not demonstrate a gain or formal equivalence.** Its ordinary-relative interval 0.975–1.005 includes parity. “No difference resolved” is stronger statistical wording than “equivalent” unless an equivalence margin was specified. Q4_0 is a meaningful stronger competitor; comparing W8A8’s absolute 80.18 tok/s from its separate track to the nine-path Q4_0 91.51 tok/s would be an invalid matched comparison.
5. **The failed QAT pilot rejects a recipe, not QAT.** The RTX 5080 BF16 cached-head KL objective improved KL 2.506→1.017 while online accepted/round fell 1.677→1.565; its trained head also damaged ordinary BF16 execution. These data motivate target alignment and online selection. They neither prove that target alignment alone will fix QAT nor supply native SM75 timing. [Source: `experiments/qat-head-pilot-results.md`.]
6. **The PyTorch/native gap is not a hardware acceptance effect.** AngelSlim used a BF16 59-proposed-node tree and llama.cpp uses FP16 and a short sequential draft. The respective ordinary accepted/round values 2.317 and 1.168 have different denominators, policies, arithmetic, and state plumbing. Do not transfer the PyTorch 38.32% linear share or 12.93% head share into an SM75 ceiling. The pilot’s optimistic 0.927× product is a BF16, one-profile planning calculation, not a universal head-W1A1 upper bound. [Sources: `experiments/pytorch-w1a1-cuda-acceptance.md`, `experiments/native-end-to-end-5080.md:149`.]

## Correct throughput and break-even relationships

For one fixed run/variant, let N be emitted output tokens, R counted speculative rounds, T the chosen decode-wall interval, A accepted drafts, and P proposed drafts. Use matching boundaries and include setup/terminal work consistently:

```
v = N/T = (N/R)/(T/R) = e/t
a = A/R
acceptance_fraction = A/P
v_candidate/v_anchor = (e_candidate/e_anchor) * (t_anchor/t_candidate)
```

The ratio is a ratio of pooled totals, not the arithmetic mean of request speedups or round-level instantaneous rates. For latency averaged over a fixed distribution of user requests, also report that separate estimand; pooled throughput gives more influence to long/slow requests.

If **every counted round** emits exactly one additional verifier token and all accepted tokens are emitted within the counted interval, then e=1+a. In real finite requests, write N=A+R+b, where b accounts for the initial token, termination, cap clipping, token-accounting conventions, and any uncounted zero-proposal/ordinary steps. Compute b from raw data; do not assume it is zero. The published native tables already show A+R=7,370 ordinary, 7,365 head/Q4_0, and 7,325 all-nine despite matching decoded text. They therefore do not justify reconstructing emitted counts from A+R.

Let d be the critical-path round cost actually removable by the proposed optimization, and c=t-d all retained work. With current emissions and retained costs fixed, a counterfactual zero-cost ceiling is:

```
v_zero_d = e/c
speedup_zero_d_vs_anchor = e/(c*v_anchor)
d_break_even = e/v_anchor - c
e_required_at_fixed_t = v_anchor*t
a_required_at_fixed_t = v_anchor*t - 1    [only when e = 1+a]
```

To beat both anchors, use the larger of their **same-run** pooled rates for the point screen, but retain direct paired uncertainty against each. A negative d_break_even rules out speedup from eliminating only that chosen work at fixed quality. A positive value is an opportunity budget, not proof that a realizable implementation can reach it. If removable work takes fraction f=d/t and is accelerated by factor s without changing anything else, the candidate speed factor is `1/(1-f+f/s)`; multiplying this by a separately changed emission ratio is a conditional model whose retained-cost assumptions must be stated.

**No numerical complete-zero-draft ceiling is recoverable from the published 2080 Ti tables alone.** The tables omit pooled N/T totals needed for a numerical residual, `draft_ms` measures only `draft()`, `process()` is untimed, and `accept_ms` is an acceptance hook rather than verifier execution. Even with N and T restored, `T-draft_ms` means the retained residual under “free draft()”, not verifier time or “free drafter.” Audit interval nesting before subtraction: host calls may include synchronization and measured prefill/terminal boundaries need to match. The 5080 report does have the additional aggregate values and reports a conditional free-`draft()` ceiling of 158.79 tok/s or 1.195× ordinary, but explicitly holds its 47.012-second residual fixed. That is neither an SM75 number nor an upper bound on removing all EAGLE work.

An exact, simpler same-run hurdle needs no verifier decomposition: at fixed emitted N, head W1A1 must remove **18.24% of its total decode time** to match Q4_0; all-nine must remove **49.40%**. Equivalently, throughput must improve 22.32% and 97.62%. These are algebraic hurdles from 74.813/91.508 and 46.305/91.508, not measured removable fractions. Do not call them kernel savings available.

When quality changes, t also changes through draft stopping, verifier batch shapes, feature catch-up, and cache repair. Thus the correct final comparison is the measured `(e_new,t_new)` pair. A break-even accepted/round threshold from one old t is not a universal QAT target.

## Acceptance needs depth, trajectory, and support information

For a fixed maximum draft depth D and accepted-prefix length L, `E[L]=sum(k=1..D) Pr(L>=k)`. Equivalently, survival to depth k is the product of conditional continuation/acceptance probabilities through k, including early stopping in the definition. Report survival, reached/proposed counts, rejection and confidence-stop counts separately; a “depth-5 accuracy” conditional on reaching depth 5 is not its unconditional contribution to emitted tokens. At a variable draft length, a low accepted/proposed fraction can coexist with useful emitted tokens/round, so neither accepted/proposed nor head top-1 agreement alone should choose a serving policy.

**Offline common-input diagnostics** ask how arithmetic perturbs the same states: activation errors, margins, reference-head agreement, target loss, and layer-output error. They are valuable causal controls. **Online candidate-policy evaluation** asks what the candidate actually proposes, how its recurrent states change, how many prefix tokens survive, and what the resulting round costs. Both are required. Off-path tree rows and stale cached ordinary/W1A1 trajectories should not be treated as interchangeable with states reached by a newly trained head. Weight examples by clearly stated policy; retain depth/parent IDs and the matched verifier row. Cached original-head KL is particularly weak as a selection criterion after the pilot.

The draft vocabulary is 32,000 mapped IDs out of 151,936, but the ratio of vocabulary sizes says nothing useful about its probability coverage. On aligned candidate-reachable and common target prefixes, measure (a) whether the target greedy token is mapped, (b) target softmax probability mass outside support, and (c) prefix runs of mapped target tokens. A mapped-support oracle for greedy decoding can show how much acceptance is impossible for any 32k-head weights on those prefixes. It is not a free runtime candidate. For exact stochastic rejection sampling with draft distribution q supported on S, the one-position expected acceptance is `sum_x min(p(x),q(x)) <= p(S)`; this follows because q=0 outside S. Greedy support indicators, stochastic mass, and sequential survival are different metrics and should not be substituted for each other. This project has not yet measured the support ceiling or validated a stochastic serving result.

W1A16 versus W1A1 with identical signs/scales is a high-information decomposition of activation damage. W1A16 still changes weight magnitudes and explicitly casts inputs, and more activation bits are not a theorem of monotonically better online acceptance in a nonlinear autoregressive model. Verify the cast-only ordinary control and use the full precision ladder, not “W1A16 is an acceptance upper bound.” Optional W8A8/W4A4 comparisons help separate weight precision at a fixed activation quantizer, but Q4_0 uses a different block-scale contract and cannot fill that factorial role.

## Statistical and correctness audit

The analysis code correctly validates complete paired records, computes pooled token/time ratios, and resamples prompt IDs and repetitions with all variants preserved (`scripts/analyze_native_benchmark.py:57`, `:79`, `:109`). The bootstrap is a crossed prompt-by-repetition resampling scheme, not 60 independent quality samples. The 2,000 draws give useful descriptive uncertainty for these large effects, but cannot account for target mismatch, workload choice, hardware systematic drift, or selecting the best of many policies.

The frozen 12 historical prompts have four prompts/category. Five deterministic greedy repetitions primarily measure timing variability, not 60 independent quality observations. Reusing these prompts to compare formats and build hypotheses means they are now a historical regression set, not a new clean final test. Do not retroactively invalidate the sealed pilot’s one-shot result; simply avoid treating another evaluation there as independent confirmation.

The new manifests have 96 train, 24 development, and 24 final prompts, balanced by category and split by topic/template family. `scripts/generate_qat_revisit_prompts.py:449` assigns the first ten families per category to training, the next three to development, and the remainder to final; `:461` expects 17 reasoning families versus 16 in each other category. The data audit's metadata-only manifest recount confirms **30 training, nine development, and ten final families**, counting topic, template, or combined family IDs. Development prose/code/reasoning has 3/3/3 families; final has 3/3/4, still eight prompts per category. Neither evaluation set supplies 24 independent topic families. Keep ordinary prompt-paired intervals for comparability, but add family-cluster resampling and leave-one-family-out sensitivity. With only three or four families/category, category-specific CIs will be unstable; report raw category/family effects without claiming broad category rankings. Large numbers of captured rows do not enlarge the independent prompt/topic sample size.

The 24 development prompts may select format/checkpoint/policy. The untouched 24 final prompts should be evaluated only after that complete choice and its analysis rule are frozen. “Once” means one prespecified evaluation campaign, which can contain all mandatory anchors and five timing repetitions; it does not mean one noisy timing sample. If it fails, stop the recipe and report the failure. A subsequent research recipe would need a separately justified new evaluation protocol, not another selection loop on this final set. The context diagnostic set is a fourth role: frozen independently, explicitly exploratory, and never silently promoted to a final quality test.

At present native speculative variants match decoded text, whereas target-only differs on one historical prompt; generated IDs were absent from the 2080 Ti responses. Text identity does not prove token identity. The native 5080 verifier trace indicates target-selected tokens at the mismatch, narrowing the problem but not proving a harmless arithmetic cause on SM75. Keep candidate-versus-FP16/Q4_0 comparisons as matched speculative-runtime observations. Do not claim strict target-equivalent speedups, even if an output difference looks like capitalization. Obtain raw emitted IDs, first divergence, target/verifier logits and state/position evidence in a bounded diagnostic. Failure to resolve the issue need not prevent reporting a negative result, but it prevents upgrading it to a lossless target-equivalent claim. New stochastic claims would additionally require the actual proposal/verifier distribution semantics.

Two analysis/tooling details matter for the new matrix:

- `analyze_native_benchmark.py` is variant-enumeration-specific and its main pooled table only names target-only/ordinary anchors. Its bootstrap does compute all available anchors. Add explicit W1Ax support and explicit Q4_0 pooled ratios/intervals rather than calculating them from rounded reports. Unit fixtures should preserve pairing and catch missing/unknown variants; no extra model run is needed for that change.
- The runner defines decode rate as **all completion tokens / server predicted_ms**, while local `server-common.h:409` explicitly says the first generated token comes from the prompt and server `n_gen_tps()` uses `n_gen-1`. This is a declared historical metric, not a hidden denominator defect, but it can inflate the displayed generation-step rate by approximately 128/127 at length 128 and 32/31 at length 32. Preserve the historical definition and additionally report actual generation-step counts/rate and end-to-end request rate in the output-length diagnostics. Verify these boundaries in the pinned timed binary; do not silently revise old results.
- The >4-variant schedule only rotates order across five repetitions (`benchmark_native_eagle.py:545`). Five rotations do not balance eight or nine variants over all time positions; prompts also run in a fixed order within each server. Preserve order, clocks, temperature and host load, inspect order sensitivity, and predeclare an improved balanced/randomized schedule for the new run if desired. Add repeats only when new ambiguity justifies them. Narrow MMA intervals do not erase these design limits.

### Specific high-information runtime diagnostics reported during the team audit

The EAGLE loop checks `params.n_max` at `common/speculative.cpp:813`, while the generic wrapper applies per-sequence `dp.n_max` after `impl->draft()` at `:2850`. This makes terminal/per-sequence overproduction a credible waste hypothesis. A CLI change to the global maximum is different from setting a per-sequence cap: the former changes the EAGLE stopping condition, the latter may only truncate finished work. Log global maximum, per-sequence cap, computed steps and retained proposals before attributing any D sweep gain to reduced arithmetic.

EAGLE uses a top-10 sampler (`:492`), checks the top candidate's stored probability (`:799`), and uses a distribution sampler in the common chain (`common/sampling.cpp:399`). On the normal top-10-renormalized CPU path, max probability is at least 0.1 mathematically, so `p_min=0.1` should be redundant with 0.0 except numerical/alternate-path behavior. Confirm the executed backend and actual confidence values in one bounded trace. The 0.3 threshold is a truncated-top-10 confidence, not calibrated full-vocabulary confidence, and quantization can shift its calibration. The frozen grid should be amended only prospectively if this diagnostic confirms redundancy; no need to spend hundreds of requests rediscovering identical policies.

The pipeline audit also flags potentially reachable norm/head/vocabulary-scatter work during `logits=false` catch-up. Treat that as a hypothesis until a graph/dispatch trace proves the operations execute and quantifies critical-path cost; a constructed node is not by itself an executed kernel. If confirmed, test its removal across FP16/Q4_0/W1Ax, not just binary, because a shared runtime saving may strengthen the competing anchors too.

### Keep the experiment count bounded

Eight primary paths × (12 historical + 24 development) × five repetitions already yield 1,440 requests. A Cartesian policy grid of 12 settings × seven speculative paths × 24 development prompts × five repetitions adds 10,080 requests before context diagnostics. That can cost more engineering/analysis attention than useful independent quality evidence. The frozen plan does specify this grid; a staged scope amendment, if desired, should be explicit before results: verify semantics, obtain deterministic quality/proposal counts once per cell, retain the declared comparisons, and spend full repeated timing on the predeclared shortlist plus both anchors. Do not quietly omit requested paths or treat one timing pass as a performance result. Repeated model execution of the same deterministic prompt is not a substitute for more independent prompts, nor a reason to touch final early.

Predeclare the primary serving endpoint and practical effect size before finalist timing. For example, a few-percent gain over **both** anchors with paired uncertainty excluding parity is a reasonable engineering target; its exact margin is a project choice, not an existing formal requirement. If repeated intervals still straddle parity and the point effect is small, label the result unresolved and stop unless an identified source of variance makes one bounded rerun informative. The existing large negative W1A1 effects do not require more repetitions merely to narrow already decisive intervals.
