# Draft pipeline optimization: local evidence audit, 2026-09-25

Scope: category 4, exact graph work elimination, fusion, memory/host transfer, attention, head selection and launch/capture costs. Local source/document research only: no web, GPU, SSH, benchmark or repository mutation. The checked-out llama.cpp is `34e21b7d85c17e25d5a91ce2ab1074d4c18bfe39`; the measured INT8/INT4 candidate `2d9712cde8d7808bb869e59e56a565e0e4fa2918` is locally available and was inspected with `git show`. References below are repository-relative, with line numbers for the checked-out revision unless a commit is specified. No implementation is proposed as already validated.

## Main conclusion and ranking

Prioritize removing unused reconciliation/prefill graph work, then shared-input packing and device-resident recurrent state. These are better justified by this source than another unconditional Tensor Core replacement. Measure complete `process + draft + target verification + accept` rounds: published `draft_ms` omits `process()`, which performs feature fusion and a whole draft decode. Do not infer its cost from the very small `accept_ms`.

## Measured foundation and limits

On RTX 2080 Ti SM75, 11,264 MiB, CUDA 12.8.93, F16 target/KV, context 2,048 and one active sequence, the nine-variant production comparison reports ordinary EAGLE 82.488 decode tok/s, Q4_0 91.508, W1A1 head 74.813 and all-group W1A1 46.305. Mean accepted drafts/round were 1.168, 1.182, 0.860 and 0.055 respectively. W1A1 all shortened the timed host `draft()` call from 6.471 to 3.558 ms/round but needed 6,940 rather than 3,400 rounds. [experiments/rtx2080ti-quantization-suite.md:183-214; experiments/rtx2080ti-synthesis.md]

At fixed token count, acceptance and all other costs, W1A1 all would need **43.9% less total decode time to match ordinary and 49.4% less to match Q4_0**; head needs 9.3% and 18.2%. These are rate-ratio arithmetic, `1 - candidate_rate / anchor_rate`, not predictions of any proposal. There is no isolated target-verifier or `process()` duration, so a rigorous zero-draft-work throughput ceiling cannot be computed from published `draft_ms` alone. The useful future bound is `tokens / (measured_total_time - disjoint_removable_draft_time)`, holding emitted tokens/round fixed; the removable span must include the relevant `process()` work and must not double count asynchronously overlapping intervals.

Published 2080 Ti component evidence is three short Nsight Systems requests per variant, profiling-instrumented pack/dot pairs, not an end-to-end attribution. The M=2,560 row merges fusion K=7,680, attention-output K=4,096 and FFN-down K=9,728; one cannot assign that pooled median to a particular layer. The source records explicitly show this grouping. [experiments/rtx2080ti-quantization-suite.md:488-576]

The earlier 5080 **PyTorch BF16 tree** diagnostic put nine linears at 38.32% and remaining graph/instrumentation at 61.68%; it used N=10 draft branches. Its optimistic 1.621x draft-event ceiling from making all linears free is already documented. It is not the native SM75 N=1 graph, does not prove attention or launch overhead occupies 61.68%, and must not be transferred numerically to this pipeline. [experiments/pytorch-w1a1-cuda-acceptance.md:82-130]

## 1. Unused graph outputs: highest-priority source finding

### Evidence chain

1. `common/speculative.cpp:604-652` gathers target features and runs the fusion encoder. `process()` then constructs decoder cache-update rows with `logits=false` at lines 688-709 and calls `llama_decode` at 716. It preserves the **encoder output** in `verify_g`/`pending_g_last`; it does not consume this cache-update decode's prenorm state.
2. `src/models/eagle3.cpp:389-529` builds Q/K/V, attention/O, FFN, prenorm, output norm, the 32,000-row head and full-vocabulary scatter unconditionally. There is no `n_outputs` guard or output-row gather; it ends with `ggml_build_forward_expand(gf, cur)` on logits. The locally inspected INT candidate has the same architecture at commit `2d9712cde:src/models/eagle3.cpp:657-807`.
3. `src/llama-graph.cpp:1362-1376` marks `t_logits` and `t_h_nextn` as outputs whenever non-null, not when the batch requests them. `ggml/src/ggml.c:7272-7291` marks the expanded nontrivial graph and its parents for computation. `src/llama-model.cpp:2762-2779` adds sampling/output markers after building the model graph; it does not replace this graph with a no-output one.
4. The `n_outputs > 0` guard at `src/llama-context.cpp:1934` guards the **host logits download**, not building or executing the head. The masked-nextn extraction similarly gates the host copy, not all ancestor computation.
5. The SM75 trace sees N=37/M=32,000 head pack+dot kernels: W1A1 all 0.890 ms, W8A8 DP4A 5.236 ms, W4A4 vector 5.359 ms per pair median. This is consistent with the batch cache-update source behavior. However there were no stage-tagged spans proving which individual host call owns each traced launch. The source shows reachable executed work; the report does not establish a measured end-to-end fraction of *unused* work.

First implement only **output norm/head/scatter elision when no logits or downstream head consumers are requested**, while keeping required prenorm output and K/V side effects. It is mathematically exact, removes an 81,920,000-weight head, and avoids full-vocabulary buffers. The head is 41.25% of the eight decoder linear parameters, excluding fusion; that is a static work/storage fraction, not a runtime fraction. At the observed N=37 trace shape, removing the whole unused head has a **local component upper limit** equal to the measured pair above, plus unmeasured norm/scatter overhead; not a guaranteed request-level saving. This may be more useful than accelerating this N=37 head with MMA.

The next stage can be **K/V-only cache reconstruction**, under an explicit call mode for this single-layer EAGLE graph when neither logits nor decoder prenorm is consumed. Each K/V vector depends only on the current token embedding, the supplied fused target feature, the two normalizations, concatenation, its linear projection, and K's RoPE/cache transformations. It does not depend on Q, attention softmax, O, FFN, output norm or head. Thus cache-update calls could retain only the input path, K/V projections, K rotation/RoPE and both cache writes. The eight decoder linears have 198,574,080 parameters; K and V total 10,485,760 (5.28%). Eliminating the other 94.72% of those linear MACs/weights for these calls is a **structural upper bound**, not 94.72% time savings or a decoder-wide bound.

`src/llama-graph.cpp:2853-2891` currently expands Q/V/K together and explicitly expands `cpy_k/cpy_v`; simply dropping the final head root is insufficient to remove Q/attention or preserve all side effects in a rewritten graph. Keep KV input indexing, rotations, cache dtype, allocation, position advancement and removal behavior intact. `common/speculative.cpp:392-425` describes the shifted pair convention: at position P use `(token[P+1], fused_target[P])`. `draft()` completes the deferred boundary and consumes decoder prenorm recurrently; **never use K/V-only there**. Existing general embedding/API callers might request prenorm without logits; zero logits alone is not a sufficient condition to skip FFN. The proposal is specific to known `process()` cache-update calls.

Mandatory correctness gate: compare retained K/V bytes (or exact codes and documented float tolerance if the existing backend already varies), all accepted-prefix lengths 0..5, pending positions/features, the first subsequent draft logits and candidate IDs, multi-ubatch prefill boundaries, cache rollback and sequence interleaving. Keep target computation/verifier unchanged. Any changed retained K/V invalidates an exact optimization claim. Merely obtaining the same final text is weaker than this gate.

Deferring reconciliation until acceptance is known also avoids rejected rows, and the source itself notes this at `common/speculative.cpp:417-425`; category 3 owns the scheduling policy. Combine only after testing graph pruning independently. There is a countervailing cost from smaller batches and extra launches, and target-aligned reconstructed K/V cannot simply be replaced with old speculative K/V generated from different recurrent draft features.

## 2. Shared packing, scales and projection fusion

`eagle3.cpp:390-399` feeds the exact same K=5,120 concatenated tensor to Q (M=4,096), K and V (M=1,024 each). Lines 444-447 feed the exact same K=2,560 tensor to FFN gate/up (M=9,728 each). Each `ggml_cuda_w1a1_mul_mat` creates separate scratch and launches `w1a1_pack_activations` (`ggml/src/ggml-cuda/w1a1.cu:84-122`). The INT candidate does likewise in `2d9712cde:ggml/src/ggml-cuda/w8a8.cu` and `w4a4.cu`.

An explicit packed-activation/scale graph value, or a narrow same-input multi-projection operator, can reduce a full decoder step from eight packs to five: Q/K/V from three to one and gate/up from two to one. Include fusion and a full encoder+decoder has nine packs reduced to six. It removes three launches and 50 KiB of repeated F32 input reading per N=1 step (2*5120*4 + 2560*4), plus reduction work. It cannot reuse between tokens, between fusion and decoder, or between FFN-down/head: those are different activations despite repeated widths. Cache by the same graph value/lifetime, not a raw address reused by the allocator.

For W1A1 all at N=1, measured K/V pack median is 5.568 us and gate/up pack 4.657 us. A rough same-input duplication budget is `2*5.568 + 4.657 = 15.793 us/step`. It is a sum of heterogeneous medians, **not a measured combined saving**. The whole head pair is 31.426 us, of which packing is 15.6%; the small M=1,024 pair is 9.152 us, packing 60.8%. This supports eliminating repeated launches for small projections, but cannot explain millisecond host draft times by itself. These component counts must be retraced after cache-update graph pruning.

Joint QKV with M=6,144 and joint gate/up M=19,456 can further reduce dot launches while preserving every weight row and row scale. Keep their distinct output views and original row ordering; a wider output matrix does **not** cure N=1 MMA tile underutilization. Gate/up can share a quantized input; down cannot share that scale because its input is `SiLU(gate)*up`. A fused gate/up epilogue or SiLU/multiply/down-pack producer can avoid intermediate buffers, but full-vector mean/absmax scaling requires a global reduction: do not independently quantize each CTA tile. Producer fusion must reproduce intermediate F32 rounding, SiLU and multiply semantics; changing accumulation order or fast math could change quantizer codes.

W1A1's packer uses sign-at-zero positive including -0, preserves negative subnormal sign via raw bits, sums abs values in FP64 and rounds the mean to F32, with masked tail bits; output order is `(float(integer_dot) * weight_scale) * activation_scale`. Preserve these properties (`w1a1.cu:7-81`). W8A8/W4A4 use whole-token absmax, existing signed ranges and nearest-even codes plus F32 row/token scales; do not substitute Q8_1 block quantization or lower-precision scales. A mathematically plausible RMSNorm/scale cancellation is not automatically code/scale-identical in floating point. This review does not recommend changing that numeric contract.

## 3. Device-resident state and synchronization

The copy path is explicit: `src/llama-context.cpp:1614-1620,2017-2025,2266-2289` downloads fusion/draft-nextn and target layer features; exported `llama_get_embeddings_nextn[_ith]` and layer-input getters call `ctx->synchronize()` at 3990-4005. `common/speculative.cpp:604-619,647-652` copies three target states into a host concat buffer and copies encoder output. `draft()` reads prenorm at 782, memcpy's it into `batch.embd` at 823, and invokes the next decode. `src/llama-graph.cpp:69-81` uploads `batch.embd` with `ggml_backend_tensor_set`.

Shapes: target features 3*2,560 F32 = 30 KiB/token; fused/prenorm 2,560 F32 = 10 KiB/token. At one sequence these bytes are modest, but the synchronization/host dependency chain repeats up to five autoregressive draft evaluations per round. Keep prenorm as a device input to the next draft graph and keep target feature/fusion staging on device. A token/candidate result may still return to the host each step; device state alone does not remove all host decisions. Stably allocated scratch plus explicit same-device stream events is necessary across target/draft contexts. Preserve accepted-row selection, target feature tap order [2,18,33], and buffer ownership across graph reuse.

Do not assert a full 151,936-logit host roundtrip each step: draft backend sampling defaults **on** (`common/common.h:332`) and `speculative.cpp:499-513` attaches a top-k(10) backend chain when supported. `needs_raw_logits()` can suppress the dense host copy. Actual timed backend success/fallback is not isolated by the published trace. First attribute runtime API synchronization and memcpy spans, distinguish idle dependency gaps from compute already counted, and compare with backend sampling success logs. Multiple getters synchronize, but only the first might wait for real work; counting calls is not counting equal stalls.

## 4. Head selection and full-vocabulary materialization

`eagle3.cpp:505-523` fills 151,936 F32 target-vocabulary logits with -infinity and scatters the 32,000 draft logits through `d2t`. This is 0.580 MiB/output (21.445 MiB for N=37), versus 0.122 MiB/output compact logits, before sampler temporaries. `experiments/qat-revisit-plan.md:66` records unique, strictly increasing absolute GGUF IDs; checkpoint `d2t` is offset-form but GGUF holds absolute IDs. Never apply the checkpoint offset convention a second time.

For this fixed top-k(10) draft sampler, choose top-k among the 32,000 finite entries, then map only selected IDs. If probabilities are computed after top-k as in the configured chain, preserve the same top-k normalization and the `p_min` stopping decision. For a different sampler needing probabilities over all supported draft IDs, calculate its exact normalization on the compact head; implicit -infinity entries add zero mass. It is not safe to change to top-1/argmax universally: ties, candidate probabilities, p_min, CPU fallback and generic API consumers need matching semantics. Preserve ordering by the existing comparator and mapped target IDs. Backend sampling already reduces host-transfer need, so the incremental value is fewer GPU fills/scatters/sorts and memory operations, not an assumed avoided host download.

A head+top-k kernel is a later possibility, but distributed selection adds reduction launches and may not beat existing top-k at N=1. Benchmark compact selection before fusing it into matrix arithmetic. Vocabulary pruning beyond the existing 32,000 rows, approximate top-k, changing draft support, skipping logits by a learned confidence rule, or replacing the head are quality changes, not this exact optimization.

## 5. GEMV versus MMA and what fusion changes

On SM75, the existing research MMA candidate is selected globally by environment flag, without shape dispatch (`2d9712cde:ggml/src/ggml-cuda/w8a8.cu`, `w4a4.cu`). Real N=1 W8A8 head costs 149.433 us default versus 434.678 us MMA; W4A4 152.650 versus 362.394. The same formats and acceptance are preserved, yet whole-run MMA/default decode ratios are 0.821 and 0.880. For N=37 head the corresponding medians are 5.236 vs 3.045 ms and 5.359 vs 2.942 ms. N=37 K/V W8A8 still loses (221.501 vs 236.136 us), so “all large N use MMA” is not sufficiently shape-specific. [experiments/rtx2080ti-quantization-suite.md:406-429,542-561]

Use vector/DP4A for demonstrated N=1 workload; benchmark crossover by N, M, K after eliminating unused calls. All nine K values are divisible by 32, but graph batch tails and generic correctness widths still matter. Real Q4_0/Q8_0 controls already select MMVQ at N=1/2 and MMQ at N=38 with Q8_1 activations, with fused N=1 path observed (`rtx2080ti-quantization-suite.md:450-467`). This existing dispatch is a useful design precedent, not permission to change the whole-token quantizer. Binary-MMA head was unresolved at 1.0017x portable end-to-end; another MMA rewrite needs a more specific data/layout bottleneck argument than instruction throughput.

## 6. CUDA graphs and ordinary fusions

CUDA graphs are already implemented. `ggml-cuda.cu:2555-2640,4410-4480` checks compatibility, caches by graph key/properties, waits for two stable calls, resets warmup when properties change, and replays through `cudaGraphLaunch`. SM75 passes the architecture threshold (Volta). The custom W1A1 op is not explicitly disallowed by the compatibility scan; its two kernels can be part of a captured graph. This proves eligibility, **not that the benchmark captured and reused a graph**, and graph replay does not eliminate hidden-state CPU roundtrips.

Record actual graph enablement/build flags, capture/replay counts, n_outputs class, source pointer/shape changes and allocation resets before building a special persistent graph. With changing KV extents and process/draft shapes, warmup may reset; current evidence gives no miss rate or launch-gap fraction. The graph framework already maintains separate prior graph state for zero/nonzero outputs (`llama-context.cpp:2422-2429`). A targeted stable N=1 graph or scratch plan may help; padding to fixed large KV lengths may add work and should not change masking, and combining autoregressive steps requires preserving token-dependent control.

Existing backend fusions include RMSNorm+mul(+add/rope) and unary-SiLU+mul (`ggml-cuda.cu:4140-4187`), plus matmul/vector fusions elsewhere. Do not claim adding SiLU+mul fusion is novel work: it is present. Custom W1A1 nodes do not match ordinary MUL_MAT fusions, so a custom same-input projection fusion is plausible, but measurement must show actual missed patterns. Fewer source ops do not necessarily mean fewer executed kernels already. FP64 W1A1 scale reduction is deliberate; reducing its precision is delegated numeric research, not an exact launch optimization.

## 7. Attention/KV: bounded lower-priority audit

The draft is one decoder layer. Q width is 4,096, K and V each 1,024; at F16 a retained position consumes 4 KiB total K/V, or 8 MiB for 2,048 positions before allocator/metadata. At logical context L, the two attention products are approximately 8,192*L MACs per query, 16.78M at L=2,048, versus 198.57M MACs in the eight dense decoder projections. Those are operation/storage counts, not measured speed ratios: packed binary linears change relative cost dramatically, and actual masks/padded cache extents and GQA reuse matter. The test context cap is not proof every request has 2,048 live positions.

`src/llama-graph.cpp:2602-2718` already supports Flash Attention with F32 accumulator, or explicit KQ, softmax and V products. The non-flash branch may make V contiguous after transpose; whether it does so in this measured model needs tracing. Determine actual selected FA path, read/write bytes, padded live context and kernel spans, then consider eliminating redundant copies or improving GQA reuse. Switching FA algorithms is mathematically equivalent but can change floating rounding and draft acceptance; prove logits/acceptance effects. Lowering KV precision, truncating context/window, altering masks or approximating softmax changes model numerics/quality and is outside exact pipeline optimization. Target attention and verifier settings remain frozen.

## Common experiment and stop gates

1. Audit stage-tagged graph/kernel counts with separate `process`, iterative `draft`, target verify and acceptance spans; report CPU wall and GPU event spans without double counting. Include actual N/M/K, KV length, graph status, backend sampler success and copy spans. No current report provides all these fields.
2. Validate exact quantizer outputs, integer dots, scaling order, retained K/V, deferred state, next proposal logits/candidates and p_min decisions on captured identical inputs; keep fixed target/verifier. Test all accepted lengths including zero and full acceptance, prefill chunk boundaries, EOS and cache rollback.
3. Run one bounded change at a time, then combine only independently useful changes. Report same-device complete-round cost and request/decode throughput with FP16 and Q4_0 EAGLE anchors; do not optimize only the W1A1 side of a comparative baseline.
4. Stop kernel tuning when measured removable cost cannot close the candidate's throughput deficit at fixed acceptance, or when a paired same-run gain is unresolved. Poor all-group W1A1 acceptance remains an independent bottleneck. The active W1Ax precision suite may change that tradeoff, but no W1Ax quality or pipeline timing is measured yet.

The native benchmark's speculative outputs match each other in the recorded paired text comparisons, but target-only differs on one prompt and generated token IDs were not available. Preserve that qualification: these pipeline experiments cannot turn those old rates into a strict target-equivalent speedup claim. [docs/EVALUATION.md; experiments/rtx2080ti-synthesis.md]
