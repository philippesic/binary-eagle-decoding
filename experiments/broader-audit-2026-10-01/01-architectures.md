# Alternative drafter architectures: prove the admission boundary first

Audit date: 2026-10-01. Project inspected at `f0bb92dda687d908b3cffe084510b3be757df54f`; local llama.cpp at `b4e366d4f0a30cac07f14d51c54c5b1329b3f485`. This is a source/literature audit, with no model execution, artifact acquisition, GPU work, or architecture pivot. The active EAGLE training experiment remains primary; Q4_0 EAGLE is the acceptance, latency and total-throughput threshold. RTX 2080 Ti remains paused.

## Decision and ranked options

**Pursue a two-day CPU compatibility fixture for the paired released DSpark/DFlash path, conditional on user selection of that backlog item.** Its purpose is to answer whether a later architecture screen can reuse our native target/capture/export infrastructure correctly. The previous architecture review already recommended this pair; repeating that recommendation does not advance the project. The new deliverable is an executable contract for feature taps, block masks, proposal alignment, private head ownership and rejection rollback. It should explicitly reject current EAGLE captures as incompatible rather than silently adapting their dimensions.

1. **Released five-layer DSpark, with matched DeepSpec DFlash control:** strongest evidence of compatible pretrained weights and existing native support. Initially retain the shared target head, Markov head and attention scaffolding at original precision; investigate W1A16 and W1A1 backbone quality only after reference admission. No confidence scheduling initially. This isolates intra-block conditioning without simultaneously changing the verifier or controller. Verdict: pursue compatibility preparation; quality screen conditional.
2. **A genuinely smaller conditioned block model:** a two-layer DSpark is the most relevant architectural hypothesis, but the inspected author release inventory provides the five-layer checkpoint, not a two-layer artifact. Removing three layers from released weights is neither the published ablation nor bounded fine-tuning from a compatible pretrained model. Verdict: defer until an author checkpoint exists or the user explicitly budgets distillation; the fixture should allow variable depth without implementing broad architecture support.
3. **Frozen-target Hydra/Medusa-1-style heads:** retain as a fallback if block memory or overhead fails. These can use rich target states with shallow predictors, but the inspected author releases target Vicuna rather than Qwen3-4B. Qwen3 needs new training, output/export contracts and possibly tree integration. Medusa-2’s joint target updates violate the frozen-target boundary. Native MTP support likewise does not provide trained MTP weights for this Qwen3 target. Verdict: defer a new head training effort, rather than treating the word “MTP” as compatibility.

Released pair availability is supported by the [DeepSpec checkpoint inventory](https://github.com/deepseek-ai/DeepSpec#released-checkpoints); Hydra’s target-specific release limitation by its [author repository](https://github.com/zankner/Hydra#model-weights). The [Medusa paper](https://arxiv.org/html/2401.10774v3) distinguishes frozen-base Medusa-1 from jointly trained Medusa-2.

## The compatibility gap is concrete

The [released DSpark config](https://huggingface.co/deepseek-ai/dspark_qwen3_4b_block7/blob/main/config.json) declares hidden width 2560, FFN width 9728, five layers, 32 query heads, eight KV heads, head dimension 128, vocabulary 151936, mask ID 151669, rank 256 and target block IDs `[1,9,17,25,33]`. Local `conversion/qwen.py` translates those IDs to native hidden-state extraction `[2,10,18,26,34]`. Current EAGLE checks use `[2,18,33]`, yielding 7680 feature columns rather than the block model’s 12800. A change in indexing convention must never be mistaken for an extra available feature: only two current taps overlap under the inspected conversion contract.

Consequently, existing prompt identities and native token ancestry are reusable; the current feature arrays, 32k head labels and EAGLE recurrent cache are not a complete training cache for DSpark. Missing taps require fresh native capture. Soft-label confidence training also needs appropriate target distributions; old hard labels do not reproduce the author objective. The completed training audit’s K/V-only prefix simplification is explicitly single-layer EAGLE reasoning, not a general permission to prune five-layer block state reconstruction.

Local DSpark conversion discards a full-vocabulary `lm_head.weight`. `src/models/dflash.cpp` then borrows the target output projection when no private draft output exists. For width 2560, the full head contains 388,956,160 weights, about 742 MiB at FP16—4.75 times the current 32k head’s rows. A separate packed W1 copy would need about 46.4 MiB for signs plus scales, new selective graph/export plumbing, and explicit ownership; modifying the borrowed tensor would alter the verifier. Keep target tensor hashes and storage identity invariant.

The rank-256 Markov tables add approximately 148 MiB at FP16. Their per-position projection is a sequential full-vocabulary operation with one active column at request concurrency one. Parallel backbone columns therefore do not eliminate the small-matrix bottleneck everywhere. Five draft layers, feature injection, full head scoring, Markov bias, argmax and discarded suffix work all belong in the round budget. This is a cost hypothesis; CPU timing cannot establish its CUDA impact.

## Two-day deliverable: a tiny native contract fixture

Day one produces a metadata-only admission manifest and deterministic tiny tensors. Record both layer-ID conventions; feature order; tokenizer and mask/EOS IDs; frozen target identities; actual proposed positions; head ownership; HF-to-GGUF transpose/RoPE permutations; and every precision exception. The reference contract uses `F[C,12800]`, fusion `[2560,12800]`, Q `[4096,2560]`, K/V `[1024,2560]`, O `[2560,4096]`, gate/up `[9728,2560]`, down `[2560,9728]`, shared head `[151936,2560]`, Markov factors `[151936,256]` and confidence `[1,2816]` plus bias. Those are mathematical orientations; GGML storage order is separately asserted. Run the toy at tiny dimensions rather than allocating real weights.

Day two, in a later authorized implementation, converts that fixture through existing DFlash/DSpark conversion and executes CPU toy rounds against an independent reference. For each anchor, draft queries see committed context and their own bidirectional noise block; they cannot see other sampled training blocks or future clean target features. Target verification stays causal. Exercise DFlash’s anchor-plus-masks layout and DSpark’s anchor-as-first-prediction layout, a first-token rejection, partial acceptance, full acceptance and EOS. Assert output-slot alignment, bonus/correction placement, rollback and reinjection; verify that replacing a private draft head leaves target outputs and tensor identity unchanged. Audit the local greedy Markov-conditioning chain explicitly before any stochastic proposal-probability claim.

Success resolves whether a bounded released-checkpoint screen is technically admissible and identifies exactly what new capture is required. Stop after two days if it needs broad runtime changes; deliver the failed contract rather than extending scope.

## Later GPU cost and strongest objection

After user approval, cap initial RTX 5080 work at two GPU-hours: admitted released references on 24 newly allocated development prompts, two valid short/full proposal settings, then selective W1A16/W1A1 backbone ablations only for surviving references. Measure prefix survival, emitted tokens, verification cost and complete rounds against same-device Q4_0 EAGLE. Training is excluded from this admission budget; only a surviving candidate earns a separately approved one-hour QAT pilot. These are proposed ceilings, not measured runtime estimates. Final SM75 conclusions await resumed 2080 Ti access.

The strongest objection is that current EAGLE training may restore sufficient quality, making another architecture unnecessary; a larger block body with an expensive shared head could lose even before quantization. Require positive measured draft budget `E/R_Q4 − C_verify − C_other` before binary engineering. A failed ceiling is a useful negative result, not justification to change target precision or relax verification.

## Plain summary

The useful next architecture task is a small bridge that proves a released block drafter can consume the right native target features and export safely. This matters because the present EAGLE data has different layer taps, vocabulary support and cache behavior. We can prepare exact metadata and toy mask, alignment and rollback cases on CPU in two days. DSpark remains the strongest later quality candidate, with matched DFlash showing whether its added conditioning pays for itself. Only a bounded GPU screen can establish acceptance and whole-round cost, and neither published speedups nor this fixture establishes one-bit robustness.
